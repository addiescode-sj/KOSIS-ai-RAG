# T2-26 LangChain 파이프라인 완성 (Linear KOS-94)

## Goal
- 완료 기준 (TASK.md 그대로): 질의 → ChromaDB(T2-24 컬렉션)에서 표 검색 → 답변 생성을 LangChain으로 한 번에 실행한다. 임베딩 모델·토크나이저는 현재 값 그대로 두고 교체 지점을 TODO로 남긴다
- Baseline: L1 test 60문항 BM25(`bm25-record`) Hit@1 0.250 · Hit@5 0.450 · MRR 0.332, 답 없음 F1 0.526
  (`evals/reports/20261029-173041-l1-bm25-record/report.md`). Chroma 검색의 L1 수치는 없음.

## Idea
현재: T2-18 체인(`chain.answer`: 후보 → 프롬프트 → 실전 1 `LLMClient` → 표 ID·연도 검증 → 코드가 출처 부착)과 tool 2개(`tools.build_tools`)는
`BaseRetriever`를 인자로 받지만 BM25에만 연결돼 있다. T2-24가 Chroma에 2,364표를 넣었지만 **질의 쪽 검색기가 없다.**

임베딩 현황 (사실 확인): 컬렉션은 Chroma 기본 EF(all-MiniLM-L6-v2)가 아니라 `index.EMBED_MODEL = nlpai-lab/KURE-v1`로 직접 계산해 넣었다
(`embedding_function=None`). 질의도 **같은 모델**이어야 하므로 `index.kure_embedder`(정규화 포함)와 `vectorstore.chroma_client`를 그대로 재사용한다.
모델·토크나이저는 T2-05/T2-04에서 바꿀 예정 → 교체 지점에 `TODO(T2-05)`/`TODO(T2-04)` 주석.

공통 구현: `retriever.py`에 `ChromaTableRetriever(BaseRetriever)` 하나 — 질의 임베딩 → `collection.query(query_embeddings=...)` →
`Document(metadata=..., score=1 - cosine distance)`. 컬렉션은 `CHROMA_COLLECTION`(.env) 필수, 컬렉션 metadata의 `embed_model`이 코드와 다르면 에러.
`evals/runners/retrieval.py`의 `build()`에 `chroma` 추가, 노트북에 Chroma로 질의→답 셀 추가. 새 CLI·모듈 없음.
옵션은 **지표를 바꾸는 변수(거절 방식·검색 조합)**가 다르다.

## Option A — Chroma 검색기만 연결 (거절은 LLM NO_MATCH)
- 접근: 공통 구현만. Chroma는 항상 k개를 돌려주므로 "후보 0" 거절이 사라지고 거절은 LLM NO_MATCH에만 의존.
- 예상 성능 향상: L1 Hit@5 0.450 → 측정. 근거 있는 추정 없음 (T2-25 대리 평가는 문항 세트가 달라 비교 불가, 같은 base 문서 29/70=0.41). 답 없음 F1: mock LLM에서는 거절 0 → 사실상 0.
- 실질 반영 이점: 질의→Chroma→답 연결(기능 완성도), 최소 코드.
- 비용·리스크: 0.3일. 예외 처리(답 없음) 후퇴 — HCX 없는 환경에서 모든 질문에 표를 추천.

## Option B — A + 코사인 임계값 거절
- 접근: `ChromaTableRetriever(min_score=τ)` — top-1 점수가 τ 미만이면 빈 목록 → 기존 체인이 LLM 호출 없이 거절. τ는 L1 dev에서 `best_tau`로 고르고 test로 측정.
- 예상 성능 향상: Hit@k는 A와 같음. 답 없음 F1이 A(≈0) → BM25 수준(0.5) 근처로 회복 기대 (근거: 같은 L1 러너가 BM25에서 dev τ로 0.526).
- 실질 반영 이점: 예외 처리(평가 2순위) 유지, T2-09 보정의 출발점, LLM 호출 수 감소.
- 비용·리스크: 0.5일. Docker·컬렉션이 떠 있어야 τ를 측정할 수 있음. 측정 전에는 `min_score=None`(끔).

## Option C — B + BM25와 RRF 결합
- 접근: B + `EnsembleRetriever` 대신 RRF 몇 줄로 BM25(`bm25-record`)와 Chroma 결과를 합침.
- 예상 성능 향상: Hit@5가 둘 중 높은 쪽 이상 기대 (근거: 표명 일치는 BM25, 개념어는 임베딩이 강하다는 일반적 결과, 이 데이터에서는 미측정).
- 실질 반영 이점: 검색 품질이 가장 높을 가능성.
- 비용·리스크: 1일+, T2-06(전민기 담당) 범위를 앞당겨 침범. RRF 점수는 임계값 의미가 달라 거절 재보정 필요.

## Recommendation
**옵션 B.** 연결과 거절 경로를 같이 지키는 가장 단순한 안이다. A는 답 없음 처리가 후퇴하고, C는 T2-06 범위다.
