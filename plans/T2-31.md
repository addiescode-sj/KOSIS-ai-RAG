# T2-31 L3·L4 계산 골든셋 표 다양화

## Goal
- 완료 기준 (TASK.md 그대로): `calculation_golden.jsonl`이 실전 1의 10개 표(조사 5종)에만 묶여 있다. 14개 조사 전체에서 표를 골라 문항을 추가하고, 사실 값은 Parquet 셀에서 코드로 뽑아 해시와 함께 남긴다
- Baseline:
  - 골든 90문항 / 고유 표 10 / 조사 5종(인구동향·인구총조사·장래인구추계·인구동태패널·지자체외국인주민) / 기관 2 — 적재된 2,364표 중 0.4%
  - 빠진 조사 9종: 영주귀국사할린동포실태조사, 출입국자및체류외국인통계, 국내인구이동통계, 세종시 특별센서스, 고령친화용품제조업실태조사, 장래가구추계, 국제인구이동통계, 주민등록인구현황, 주택총조사
  - 표 쏠림: `101_DT_1B8000H` 하나가 25/90 (28%)
  - L3 PASS 86/90 (T1-27 재채점), L4 PASS 25/90, 검색 1위 정답 16/90 (`evals/reports/20261031-204949-T2-15-live-e2e/`)
- 영향 범위: L3(`runners/stat.py`)와 L4(`runners/e2e.py`)가 같은 골든을 쓴다. L1 검색 골든(117문항, 고유 표 240)은 이미 다양하므로 범위 밖.

## Idea
1. 표 표본: `data/tables.jsonl`에서 조사별로 층화 추출 (조사당 2~5표, 인구총조사는 메뉴 하위 부문별로). `coverage=A_정상`만, 시드 고정.
2. 문항 생성: 표마다 Parquet을 읽어 셀을 고르고 유형별 문항을 만든다 — value · compare(두 분류 차이/배수) · trend(두 시점 증감률) · not_answerable(no_period: 수록기간 밖 연도, missing_value: `X`/`-` 셀, no_item: 그 표에 없는 항목). **값·파생값은 pandas가 계산**하고 `source_ref`(=`Cell.ref()`), `table_sha256`을 같이 쓴다. '계'·'소계' 셀은 비교 대상에서 뺀다.
3. 새 빌더 `evals/builders/diverse.py` → **별도 파일** `evals/datasets/calculation_golden_diverse.jsonl`(+ `.meta.json`), `qid` 접두사 `D-`. `phase1.py`가 `calculation_golden.jsonl`을 통째로 덮어쓰므로 같은 파일에 합치지 않는다. 해시 검사는 `phase1.py`의 `sha256()`만 import해서 쓴다.
4. `run_eval.py` l3/e2e에 `--calc-golden PATH`(여러 개 가능, 기본은 기존 파일 하나)를 추가해 두 파일을 함께 읽는다.
5. 측정: 표·조사 분포 카운트, oracle 자기검증(정답 facts로 만든 StatAnswer가 기존 채점기에서 PASS — 생성 버그 검출), L3·L4 1회 실행해 전→후 기록. 성능 수치는 **추정하지 않고 실행 후 측정값으로 채운다.**

## Option A — 템플릿 질문 (결정적, 최소안)
- 접근: 위 1~5. 질문은 템플릿 `"{period}년 {dim_label} {item_name}({unit})은(는)?"`. LLM·세션 작성 없음.
- 예상 효과: 고유 표 10 → ~55, 조사 5 → 14, 최대 표 비중 28% → ~12% (산술). 문항 +~150. 지표는 "개선"이 아니라 커버리지 확대. 검색 난도 영향은 *추정*: 질문에 표의 항목명이 그대로 들어가 L4 검색이 실제보다 쉬워질 수 있음 (근거 약함 — L1 exact_name Hit@1도 0.40~0.64라 확실하지 않음, 실행 후 확인).
- 실질 반영 이점: 데이터 정확성(값 100% 코드 산출·해시 고정), 언제든 재생성. 종합 단계 툴 평가에 재사용.
- 비용·리스크: 반나절. 질문이 기계적이라 질의 이해(L2) 평가로는 쓸모가 적음.

## Option B — 코드 facts + 자연어 질문 1회 작성 + 결정적 검사 (균형안)
- 접근: A와 같은 facts에 대해 질문 문장만 세션 안에서 Claude가 구어체로 한 번 쓴다(T2-02 방식, API 비용 없음). 문장은 결정적 검사를 통과해야 채택: ① 정답 fact의 연도 ② 지역·분류 라벨(또는 별칭 표) ③ **항목명 핵심어 또는 별칭**(출생건수 vs 조출생률 같은 혼동 방지) ④ 문장 속 숫자는 연도·라벨 숫자뿐. 실패하면 템플릿 문장을 쓴다. 20% 표본을 `calculation_review_sample.csv`로 내보내 사람이 검수.
- 예상 효과: 분포는 A와 같음. 질문이 실제 사용자 말투에 가까워 L4 수치가 더 현실적 (*추정*, 실행 후 측정).
- 실질 반영 이점: 정확성은 A와 같고(숫자는 코드), 질의 이해·L4 검색 평가가 현실화됨. 발표 근거: "10표 → ~55표, 조사 5 → 14"와 새 표에서 생긴 실패 유형.
- 비용·리스크: A + 2~3시간. 라벨러=Claude라 사람 검수 표본이 필요(T2-02와 같은 한계).

## Option C — L1 검색 골든 질문 재사용 (질문 먼저, facts는 나중)
- 접근: 새 질문을 만들지 않고, 이미 자연어로 된 L1 검색 골든(117문항, 고유 표 240)에서 정답 표가 하나이고 단일 셀·두 셀로 답할 수 있는 문항을 고른다. 빌더가 질문의 슬롯(`query_golden.jsonl`의 연도·지역·measure)으로 정답 표 Parquet에서 셀을 찾아 facts를 붙이고, 셀이 정확히 하나로 정해지지 않는 문항은 버린다.
- 예상 효과: 쓸 수 있는 문항 ~40~60, 표 ~40 (*추정*: 117 중 답 없음 24%, 복합 9 제외, 슬롯으로 셀이 하나로 정해지는 비율을 모름). L1·L2·L4가 같은 질문을 쓰게 되어 계층별 실패 원인을 같은 문항에서 추적할 수 있음.
- 실질 반영 이점: 질문이 사람(멘토 PoC·시나리오) 기준이라 가장 현실적, 계층 간 연결.
- 비용·리스크: 반나절~하루. 슬롯→셀 매핑이 모호한 문항이 많으면 문항 수가 적어짐. 조사 14종 전부를 덮는다는 보장이 없음(L1 골든 분포를 따름).

## Recommendation
**B.** 14개 조사를 모두 덮는 것을 보장하는 건 A·B뿐이고, 숫자는 둘 다 코드가 뽑는다. B는 비용 2~3시간을 더 들여 질문이 현실적이 된다. C는 계층 연결이 장점이지만 커버리지를 보장하지 못하니 후속 과제로 남긴다.
