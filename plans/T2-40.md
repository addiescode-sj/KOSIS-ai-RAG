# T2-39 역HyDE: 표마다 가상 질문 색인 (Doc2Query−− 방식, 노드화)

## Goal
- 완료 기준: 표 2,364개마다 "사람이 이 표를 찾을 때 던질 질문"을 오프라인으로 만들고(gpt-4o-mini), 규칙 + 1차 리랭커 점수로 거른 뒤
  **별도 질문 색인**(Chroma dense + BM25)으로 둔다. 질의 시에는 LLM 호출 없이 질문↔가상 질문을 맞춰 표 순위를 하나 더 만들고
  dense·BM25와 RRF로 합친다. 검색 골든 89문항에서 S0 대비 Hit@1·Hit@5를 질문 단위 짝 bootstrap으로 판정한다.
- 근거: 리서치 56(변형 B 추천), 계획 57(D1~D5 추천안 확정, 11/03 16:17), 예시 57a. 사용자 지시: 생성 모델 gpt-4o-mini,
  **노드화가 가능한 작업은 모두 LangGraph 노드로**.
- Baseline (검색 골든 89, 답 있음): 하이브리드 + 조건 슬롯 + 학습 1차 리랭커 **Hit@1 .438 / Hit@5 .685**.
  남은 실패: 개념 → 지표 매핑(저겹침 약 28%), 형제 표(기간·주기·지역 수준만 다름).
- 원칙: 골든 질문·정답을 프롬프트·규칙·필터에 쓰지 않는다(전역 규칙만). 사람 골든(human_e2e)은 보지 않는다.

## Idea
1. **오프라인 생성 그래프** `kosis_rag/hq/graph.py` — 표 하나 = `HqState` 하나.
   `load → prompt → generate → validate(실패 시 1회 재요청) → rule_check → score` 표 단위 그래프를,
   바깥 그래프 `generate_all → filter_all → write`가 스레드 풀(기본 8)로 돌린다.
   캐시 `data/hq/cache/<prompt_hash8>/<model>/<key>-<user8>.json`(원문·토큰·시간; user8 = 표 user 메시지(n2 문서 + 필드 요약)의
   sha256 앞 8자리라 표 내용이 바뀌면 miss): 캐시가 있으면 API 호출 0, 끊겨도 이어 돌림.
   빌드 id `hq-<prompt8>-<tables8>-<model>-f<제거%>[-k<min_keep>][-n<limit>]`(예: `hq-1a2b3c4d-5e6f7a8b-gpt-4o-mini-f30-k2`,
   점수 필터 끔은 `-f0`): 모델·필터 설정이 다른 빌드는 폴더·Chroma 컬렉션이 따로 생긴다.
2. **프롬프트**(고정, `PROMPT_VERSION`): n2 표 문서 + 필드 요약(측정 대상, 분류, 수록 연도, 주기, 지역 수준, 시도, 단위).
   질문 6개 = 개념형 2 · 조건형 2 · 구별형 1 · 키워드형 1. 수치 금지, 표에 없는 연도·지역 금지, 표 이름 복사 금지, "이 표" 금지.
3. **걸러내기(Doc2Query−−)**: 규칙(연도가 수록 연도 밖, 시도가 표 지역 밖, 연도·나이 아닌 수치, 표 이름과 유사도 ≥ 0.9,
   같은 표 안 중복 ≥ 0.95, 지시어) → 1차 리랭커(질문, 자기 표 n2) 점수 전체 하위 30% 제거, 표당 최소 2개 보장.
   자기 표 검색 순위로는 거르지 않는다(어휘 격차 질문이 빠지므로).
4. **질문 색인** `kosis_rag/hq/index.py`: 질문 1개 = Chroma 문서 1개(metadata key·type), 서비스와 같은 미세조정 임베더.
   컬렉션 `kosis_hq__<build_id>__<ckpt8>`. `HqRetriever`: 질문 상위 200 → 표별 max-pool → 상위 50표(본문은 n2 표 문서라
   리랭커는 지금처럼 n2를 본다). BM25(S2): 표 1개 = 남은 질문을 이은 문서 1개.
5. **질의 그래프** `kosis_rag/graph.py`: `retrieve`를 나눈다.
   `parse → condition → (retrieve_dense ∥ retrieve_bm25 ∥ [retrieve_hq] ∥ [retrieve_hq_bm25]) → fuse → [rerank1] → [rerank2] → gate`.
   병렬 가지는 `SearchState.runs`(목록 이름 → 순위 목록)와 `run_removed`에 dict 병합 reducer로 쓰고, `fuse`가 RRF(가중치 `HQ_WEIGHT`)로 합친다.
   질문을 임베딩하는 목록이 둘 이상(dense + hq)이면 `condition` 뒤 `embed` 노드가 질문을 한 번만 임베딩해 두 가지에 같은 벡터를 준다
   (같은 임베더를 두 스레드가 동시에 부르지 않음). HQ 끔이면 `embed` 노드도 없다.
   HQ가 꺼지면 `retrieve_hq` 노드를 붙이지 않고, 결과(docs 순서·metadata, removed, relaxed, route, result)는 지금 그래프와 같다(테스트로 고정).
6. **설정**: `.env`의 `HQ_BUILD`(빈칸 = 끔), `HQ_WEIGHT`(기본 1.0), `HQ_BM25`(on/off). `SearchSettings.label()`에 `+hq`·`+hqbm25`.

## Option A — 별도 질문 색인 + retrieve 노드 분할 + fuse (D1 a, D2 a, D3 a)
- 접근: Idea 1~6 그대로. `hybrid_search`를 `condition_filter`·`search_list`·`rrf_fuse`로 나누고 `hybrid_search`·`HybridRetriever`는 같은 동작으로 그 셋을 부른다.
- 예상 성능 향상(판단): 개념형·저겹침 문항에서 Hit@5 +2~4문항, Hit@1 +1~3문항. 형제 문항은 구별형 질문으로 손실 ≤ 1 목표.
  지연 +수십 ms(벡터 검색 1회, 질의 시 LLM 0회).
- 실질 반영 이점: 노드별 trace로 어느 목록이 정답을 찾았는지 보인다(`rank_<목록>` metadata). 걸러진 질문은 재학습 데이터로도 쓴다(계획 57 §8).
- 비용·리스크: API 약 2,364회(+재요청), gpt-4o-mini 기준 약 $1 안팎(단가는 사용자가 `evals/pricing.json`에 채움). 그래프 노드 이름이 바뀌어
  기존 노드 이름 테스트(test_graph의 span·trace 이름)를 새 이름으로 고친다.

## Option B — 가상 질문을 n2 문서 본문에 덧붙이기 (D1 b)
- 접근: 표 문서 끝에 질문 줄을 붙여 dense·BM25 색인을 다시 만든다. 그래프 변경 없음.
- 예상 성능 향상: 개념형 일부 이득 가능하나 n3 폐기 때처럼 형제 표가 섞일 위험(점검 55). 리랭커가 n2로 학습돼 입력 불일치.
- 비용·리스크: 재색인·재학습 필요. 채택하지 않음.

## Option C — retrieve는 두고 뒤에 hq 합치는 노드만 추가 (D2 b, 2단 RRF)
- 접근: 지금 `retrieve` 결과와 hq 목록을 한 번 더 RRF.
- 예상 성능 향상: A와 비슷하나 2단 RRF라 가중치 의미가 흐리고, 목록별 trace가 안 보인다.
- 비용·리스크: 코드는 작지만 "노드화 가능한 건 노드화" 지시와 맞지 않음. 채택하지 않음.

## Eval
- 주 판정: 검색 골든 89(답 있음, dev 29 / test 60), `lab/hq_eval.py`가 `build_graph`로 S0·S1·S2·S1-w.5(+ S1-nofilter, S1-desc)를 돌린다.
  dev에서 S1/S2/w를 고르고 test는 고른 1개만 1회. Hit@1/5/10, MRR@10, rerank1 전 Recall@50, S0 대비 질문 단위 짝 bootstrap 95%(10k, seed 0),
  qtype별(sibling·concept·저겹침), 승/패, 노드별 지연 p50/p95.
- 오염 점검(필수): 골든 질문마다 가장 가까운 가상 질문과의 cos(같은 임베더)·difflib 유사도, 0.9 이상 비율과 그 문항을 뺀 성능.
- 채택: Hit@1 ≥ .461(+2문항) 또는 Hit@5 ≥ .708(+2문항), 다른 쪽이 유의하게 떨어지지 않음.
  가드레일: Recall@50 하락 없음, 형제 Hit@1 손실 ≤ 1, 저겹침 승:패 ≥ 2:1, 검색 지연 p95 +150ms 이하.
  폐기: S1·S2 모두 ±1문항 안이거나 오염 제외 후 이득이 사라질 때.
- 보조: 팀 L1 골든 v2 test `run_eval --layer l1 --retriever graph:staged`(`.env`의 `HQ_BUILD` on/off).
