## Context (2026-11-02 확인)
- 이미 있는 것: `filters.table_regions`(시도, 옛 이름 통합, 행정구역 분류 없으면 None), `filters.REGION_LEVEL_DIMS`·`has_dimension`(시도/시군구/읍면동), `roles.table_roles`(measure·dimensions, T2-27), `TableRecord.periods`·`cycle`·`unit`·`classes[].levels`.

- 단위 화이트리스트(고정): 명·가구·건·%·호·세·천명당·개·명/㎢·세대·만원·원·천원·개월·㎡·쌍. 집계 스크립트는 `scripts/field_profile.py`에 같은 목록으로 둔다.

- 멘토 예시: 목록 `A11_2015_1_10`에 29표, 그중 이동자유형별 인구는 `101_DT_1PB1607`(읍면동, 2016~2025, 행정구역 3,508라벨·성·연령)과 `101_DT_1PB2009`.
- "연도 끝자리 0, 5" 표: 표 이름에 쓰인 것 5표. 읍면동 값은 0·5년에만 있고 나머지 해는 시군구까지만 있다 → 표 단위 `available_years`로는 "2023년 읍면동"을 걸러내지 못한다(B2 리뷰 항목).

## Idea
1. **스키마** `TableFields`(Pydantic, `src/kosis_rag/fields.py`)와 `table_fields(record) -> TableFields`. `TableRecord`·`tables.jsonl`은 바꾸지 않고 레코드에서 계산한다(T2-27 `table_roles`와 같은 방식, 스키마 호환 문제 없음).
   - `available_years: list[int]`, `cycle: list[str]`(evaluator와 같이 `record.cycle or record.prd_se`), `regions: list[str] | None`(None = 행정구역 분류 없음, 전국 표), `region_level: list[str]`, `measure: str | None`, `measure_unit: str | None`, `dimensions: list[str]`(이 단계는 원래 이름, 표준화는 A2).
   - 필드 이름은 KOS-96·T2-28 문서 이름을 그대로 쓴다. 평가 evaluator의 `years`는 `available_years`, `regions == "none"`은 `None`, `cycle`은 같은 대체 규칙(`cycle or prd_se`)이라는 대응표를 리포트에 적어 평가 쪽이 바로 바꿔 쓸 수 있게 한다(평가 코드는 고치지 않음).
2. **프로파일 리포트** `scripts/field_profile.py` → `docs/reports/t2-30-fields.md`: 필드별 채움률·고유값 수·상위 10개, 해당 없음(전국 표의 regions/region_level) 따로 셈. 골든 문항·정답 표 key는 넣지 않는다(T2-02 규칙, 집계만).
3. **KOS-92 확인**: "출생"·"혼인"이 든 표에서 (measure, dimensions) 조합이 몇 갈래로 나뉘는지, 세는 대상 표와 분류 역할 표가 measure로 갈리는지 집계.
4. **멘토 예시 1건**: `101_DT_1PB1607`의 필드 값을 리포트에 그대로 싣는다.
5. pytest: 전국 표(regions None), 단위 없는 표, 멘토 예시와 같은 모양의 가짜 레코드.

## Option A — 기존 함수 묶기 (단위는 표 단위만)
- 접근: 1~5번. `measure_unit = record.unit`만 쓴다. B는 A에 단위 보충 한 단계를 더한 것이라 A는 B의 하위 단계다(리뷰 지적, 실제 다른 접근은 C).
- 예상 성능 향상: 검색 지표 직접 변화 없음(스키마 단계). L0 채움률 measure_unit 0 → 62.3%, 나머지 5필드는 evaluator 수치와 같음. 근거: 위 프로파일.
- 실질 반영 이점: A2·A3와 전민기 님 A4·A5가 쓸 필드 이름·타입이 오늘 고정된다. 평가 L0가 같은 정의로 잰다(데이터 정확성·기술 설계).
- 비용·리스크: 1~1.5시간. 단위 없는 891표(37.7%)가 그대로 남는다.

## Option B — A + 항목 이름에서 단위 보충 (추천)
- 접근: A + 표 단위가 없으면 항목 이름 끝 괄호를 화이트리스트로 읽어, **모든 항목이 같은 단위일 때만** 그 단위를 채운다. 일부 항목에만 단위가 있거나(괄호 없는 항목이 %·원일 수 있음) 단위가 섞인 표는 `None`으로 두고 개수만 리포트에 남긴다(새 필드 없음). "15세 이상"처럼 단위가 아닌 괄호는 버린다.
- 예상 성능 향상: L0 채움률 measure_unit 62.3% → 66.5%(+100표). 검색 지표 직접 변화 없음. 근거: 위 집계(화이트리스트 고정).
- 실질 반영 이점: CLAUDE.md "단위 다름" 거절(T2-09)과 실전 1 숫자 계산의 단위 확인에 쓸 근거가 늘어난다. 부분·혼합 표를 "단위 하나"로 단정하지 않는다(데이터 정확성).
- 비용·리스크: 1.5시간. 화이트리스트 밖 단위는 놓친다 → 미매핑 괄호 상위 값을 리포트에 남겨 A2 단위 사전에서 넓힌다.

## Option C — B + 지역 단위별 수록 연도 (Parquet 값에서)
- 접근: B + `level_years: dict[str, list[int]]`(예: 읍면동 [2015, 2020, 2025], 시군구 2016~2025). 표마다 Parquet 값을 읽어 지역 단위별로 값이 있는 해를 모은다. `tables.jsonl` 생성(`metadata.py`)에 넣어야 해서 재생성(약 3분)과 팀원 재생성 안내가 따라온다.
- 예상 성능 향상: "2023년 ○○동" 같은 질문에서 읍면동 값이 없는 해의 표를 거를 수 있다. 해당 표는 이름에 드러난 것 5표 + 이름에 안 드러난 표(미확인). 검색 지표 변화는 해당 문항이 dev에 거의 없어 작을 것.
- 실질 반영 이점: B2 리뷰가 지적한 "읍면동 연도 끝자리 0·5" 필터 오통과를 데이터 쪽에서 막는다.
- 비용·리스크: 반나절 이상. `tables.jsonl` 형식이 바뀌어 A2·A3 일정(오늘 마감)과 겹치고 팀원 재생성이 또 필요하다. 필터 쪽(`filters.py`) 변경까지 따라와 A1 범위를 넘는다.

## Recommendation
**Option B.** A1 완료 조건(스키마·리포트·예시)을 오늘 채우면서, A와 비용 차이가 작고 단위 필드를 실제로 넓힌다. 모든 항목이 같을 때만 채워 단위를 잘못 단정하지 않는다. C의 지역 단위별 연도는 필요하지만 `tables.jsonl` 재생성과 필터 변경이 따라와, A2·A3를 막지 않도록 A7(실패 문항 기반 개선)이나 별도 이슈로 넘기고 리포트에 "알려진 한계"로 적는다.

# 2단계 A2 — 지역·분류·단위 정규화 사전 + 필드 추출 전처리 (Linear KOS-97)

## Goal (A2)
