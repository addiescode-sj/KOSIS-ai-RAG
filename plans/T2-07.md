# T2-07 리랭커 (1차 학습된 bge 리랭커 → 2차 교체 가능한 LLM 리랭커)

## Goal
- 완료 기준 (TASK.md 그대로): 리랭커 — GPT-4o mini LLM 리랭커 도입 검토. 하이브리드 상위 20개 listwise 재정렬·표 ID 보존(KOS-106) → 없음 vs GPT-4o mini (vs 클로바 스튜디오 리랭커, 선택) 비교·채택 결정(KOS-107) → 지연·토큰·비용 계측(KOS-108). 완료 기준: Hit@1·MRR·지연 p50/p95·질의당 비용 비교표와 결정 근거
- 구조 (11/02 전민기 지시): 학습된 bge-m3 하이브리드(T2-06) → **1차** 학습된 bge-reranker-v2-m3 → **2차** CLOVA 리랭커(질문 감싸기). 2차는 나중에 다른 LLM 리랭커로 바꿀 수 있게 한다.
- 의존 변경: TASK.md는 T2-07이 T2-29 뒤라고 적었지만, 이 plan은 T2-06(하이브리드 + T2-14 필터) 위에 만든다. T2-29 슬롯 추출기는 `build_search`의 필터 자리에 나중에 들어간다.
- Baseline: 리랭커 **없음**. 입력은 T2-06 결과(dev 29 값은 T2-06 Result).
- 참고 (min 브랜치 `lab/`, 검색 골든 답 있음 89문항, Hit@1/5/10, MRR@10, **탐색적: 이 골든으로 설정을 골랐음**):
  - 입력(F0 + 소프트 재점수): 0.427 / 0.652 / 0.730, 0.521
  - 학습 안 한 bge-reranker-v2-m3: 0.326 / 0.539 / 0.685 (순서를 망침)
  - 학습한 리랭커 e2, 입력 순위와 RRF(blend): 0.438 / 0.685 / 0.764, 0.545. 표 단위 95% 구간이 0을 지나 효과 미확정(Hit@5 4승 1패). dev 29: 16/20/21, 0.606. 질문당 0.41초(GPU, 상위 50).
  - CLOVA 리랭커만 + 질문 감싸기(상위 20): Hit@1 0.494, Hit@5 0.674. 감싸기 문구도 이 골든으로 골랐다.
  - 1차 → CLOVA 2단계를 검색 골든으로 잰 값은 없다. e2e(실전 1 골든 90) 1위 표 26/90은 미세조정 임베딩·리랭커·CLOVA 전체의 효과(KURE 하이브리드 14/90 대비)라 리랭커만의 효과가 아니다.
  - 리랭커 학습: 합성 질문 unseen 5,636문항, 정답 1 + 네거티브 7 그룹 softmax, 위 8층 + 헤드, 2 epoch, Colab. 학습 코드는 min `lab/rerank_ft_*.py`에 둔다.

## Idea
1. `src/kosis_rag/model.py`: `load_cross_encoder(base, ckpt)` — bge-reranker-v2-m3 위에 학습한 층(`.pt`)을 덮어 불러오고 GPU면 fp16. 경로는 `.env` `RERANK_CKPT`(비우면 1차 없음).
2. `src/kosis_rag/rerank.py`(신규):
   - `CrossEncoderReranker(base, score, n=50, mode="blend"|"score")`: 입력 상위 n을 (n2 질의, n2 표 텍스트) 점수로 재정렬. blend = 1/(60+리랭커 순위) + 1/(60+입력 순위). n 밖은 뒤에 그대로.
   - `LLMReranker(base, select, k_in=20, name)`: 상위 k_in 표 키를 2차 선택 함수에 주고, 고른 표를 앞으로(1차 순서 유지), 나머지는 뒤. **표 ID는 입력 키와의 교집합만 쓴다(KOS-106)**. 호출 실패·시간 초과면 1차 순서 + `stage2_error`.
   - `LLM_RERANKERS: dict[str, factory]` 등록표. 이번에는 `"clova"` 하나. 새 LLM 리랭커는 `select(question, keys) -> list[key]` 함수 하나만 등록.
   - 각 단계는 LangChain `BaseRetriever`라 `chain.search`·`chain.answer`·evals가 그대로 받는다.
3. 점수와 거절: `metadata["score"]`(T2-09 답 없음 임계값이 보는 값)는 T2-06의 dense 코사인을 **바꾸지 않는다**. 1차 점수(sigmoid 확률)는 `stage1_score`로 따로 남겨 T2-09가 임계값 후보로 쓸 수 있게 한다. CLOVA가 아무 표도 인용하지 않으면(`stage2_cited_n=0`) 순서는 1차 그대로 두고 그 사실을 metadata로 남긴다. 거절 여부는 이 신호를 받아 T2-09에서 정한다(여기서 거절하지 않음).
4. `src/kosis_rag/clova.py`(신규): CLOVA Studio `/v1/api-tools/reranker` 호출(재시도·간격), 질문 감싸기 `"다음 질문의 수치를 찾을 수 있는 통계표: {q}"`, 응답 `citedDocuments`에서 표 키만 뽑기. 키는 `chain.clova_chat`과 같은 `load_env`·`get_secret` 경로(레포 `.env`의 `HCX_API_KEY`)를 쓴다. HTTP는 urllib, 새 의존성 없음.
5. 계측(KOS-108): urllib 호출은 `UsageCallback`에 잡히지 않으므로, 2차 단계가 metadata에 `stage2_calls`, `stage2_seconds`, 응답에 사용량이 있으면 토큰을 남긴다. 1차는 `stage1_seconds`. runner 집계 연결은 평가 엔지니어링(이선주)과 맞춘다.
6. `src/kosis_rag/pipeline.py`(신규): `build_search(settings) -> BaseRetriever` — T2-06 하이브리드(+조건 필터) → 1차 → 2차를 `.env`(`EMBED_CKPT`, `COND_FILTER`, `RERANK_CKPT`, `RERANK_MODE=blend`, `STAGE2=clova|none`)대로 조립. `tools.search_tables`·`chain.answer`가 이 함수 하나로 검색기를 얻는다.
7. evals: `retrieval.build`에 `staged`(1차만), `staged-clova`(1차+2차), `clova-only`(하이브리드 + 2차) 이름. 공식 측정은 평가 엔지니어링.
8. tests(모델·API 없이 가짜 점수·가짜 선택 함수): blend 계산과 동점, n 밖 꼬리 유지, 2차 인용 앞으로·순서 유지, 모르는 키 무시, 예외 시 1차 순서, 인용 0개, 빈 후보, `score` 불변.

## Option A — CLOVA만 (하이브리드 상위 20 → CLOVA 감싸기, cross-encoder 없음)
- 접근: Idea 2의 `LLMReranker`·3~8만. `RERANK_CKPT` 없음. GPU·400MB 가중치 불필요.
- 예상 성능 향상: lab에서 Hit@1 0.427 → 0.494, Hit@5 0.652 → 0.674 (89문항, 탐색적, 감싸기 문구가 이 골든으로 고른 것이라 낙관적).
- 실질 반영 이점: 가장 단순하다. 서버에 GPU가 없어도 된다. HCX 키 하나로 끝난다.
- 비용·리스크: 반나절. 질문당 CLOVA 1회. API가 실패하면 하이브리드 순서로 돌아가 리랭커 효과가 0이 된다. 상위 20 밖 정답(lab 입력 기준 6~50위 문항 중 일부)은 못 올린다.

## Option B — 1차 학습된 cross-encoder + 2차 CLOVA (사용자 구조, 추천)
- 접근: Idea 1~8 전부. 같은 dev로 **없음 / 1차만 / CLOVA만 / 1차+CLOVA** 네 가지를 `.env` 스위치로 나란히 잰다(A도 함께 측정됨).
- 예상 성능 향상: 1차만 Hit@1 0.427 → 0.438, Hit@5 0.652 → 0.685(lab, 효과 미확정). 1차+CLOVA는 **미측정**: 1차가 6~50위 정답 18문항을 올리고 3문항을 내려 CLOVA 입력 상위 20이 좋아지므로 CLOVA만(0.494)보다 높기를 기대하지만, 두 단계 합성은 근거가 아니다. 결과는 탐색적으로 적고 새 확인 세트에서 다시 본다.
- 실질 반영 이점: 사용자 구조 그대로이고, 2차가 실패해도 1차 순서가 남는다(예외 처리). 2차 자리가 등록표라 GPT-4o mini는 함수 하나로 추가한다.
- 비용·리스크: 1일. GPU 0.4초 + CLOVA 1회. 가중치 전달(Drive). CLOVA는 점수 없이 인용 표만 돌려주므로 MRR은 "인용 앞, 나머지 1차 순서"로 계산된다.

## Option C — B + GPT-4o mini listwise 2차를 함께 넣고 비교
- 접근: B에 `"gpt-4o-mini"` 2차를 추가(상위 20 표 텍스트를 주고 표 키 순서를 JSON으로 받음, Pydantic 검사, 입력에 없는 키는 버림). 없음 / 1차 / 1차+CLOVA / 1차+GPT-4o mini 비교표로 채택 결정(KOS-107).
- 예상 성능 향상: GPT-4o mini 쪽은 근거 없음(미측정).
- 실질 반영 이점: TASK 완료 기준(비교표·결정 근거)을 문구 그대로 채운다.
- 비용·리스크: B + 1일. OpenAI 키·비용 필요(팀 키 유무 확인 필요). 표 텍스트 20개(약 9천 자)라 질의당 토큰이 크다. 마감 11/03과 겹친다.

## Result
