# T2-14 기간·주기 후보 필터 규칙 초안 (H3) + 지역·분류 메타데이터 필터

## Goal
- 완료 기준 (TASK.md 그대로): 표를 선정하기 전에 질문의 기간·주기와 표의 수록기간·주기(월·분기·연, 인구총조사 5년 주기)를 대조해 후보를 거르는 규칙 초안을 만든다
- 함께 해야 하는 것 (T2-03 Decision B): L2 질의 이해 골든(`query_golden.jsonl`, 필드: 기간 시작·끝, 주기, 지역, answerable)과 evaluator는 **T2-14가 파서 출력 형식을 정한 뒤** 만든다.
- 멘토 답변 반영 (11/1 멘토링, Q2·Q5): 지역·연도·분류 차원은 임베딩 문서가 아니라 **메타데이터 필드로 두고 질문에서 뽑은 조건으로 거른다**. 단위는 임베딩보다 메타데이터 필드로 둔다. 예: "2025년 서울 인구 이동자 수" → 서울 → 서울특별시, 2025년 자료가 있는 표인지 확인, 성별·연령 조건이 없으면 그 필터는 걸지 않음.
- Baseline (T2-05, 2026-10-30, T2-02 골든셋 dev 답 있음 29문항):
  - 질문 → 조건 파서: **없음**. `TableFilter`(연도·주기·기관, `src/kosis_rag/filters.py`)는 있지만 값을 사람이 넣는다.
  - 검색: 벡터 KURE-v1 Hit@1/5/10 10/13/15, MRR 0.401. BM25(전체 라벨) 8/13/13, MRR 0.316.
  - 연도 필터 (정규식으로 뽑은 연도, 14문항): strict는 정답 제거 2, partial은 0. Hit@1/5/10 1/3/5 → 2/4/5 (partial).
  - 골든셋에서 조건이 나오는 질문 (키워드 집계): dev 39 중 연도 17 · 시도 이름 6 · 주기 표현 11 · 지역 단위(시군구·읍면동 등) 5, test 78 중 연도 24 · 시도 11 · 주기 9 · 지역 단위 20.
  - L2 질의 이해: 골든·evaluator 없음 (`evals/schemas.py`의 `QueryItem` 스키마만 있음).
  - 거절: `chain.answer`는 검색 결과가 0건일 때만 거절한다(`TODO(T2-14, T2-09)`).

## Idea
1. **파서 출력 모델** `ParsedQuery`(새 Pydantic 모델, `src/kosis_rag/query.py`): `period_start`·`period_end`("YYYY" 또는 "YYYYMM"), `years`(질문에 나온 연도 목록), `cycle`(Y/Q/M/F), `regions`(시도 정식 이름), `recent`("최근 N년/개월" 표현이 있었는지). 변환 함수 두 개를 둔다.
   - `to_filter() -> TableFilter`: 검색 필터 판정용.
   - `to_query_item()`: L2 `QueryItem` 필드와 같은 모양으로 바꿔 채점한다. `answerable`은 파서가 판단하지 않는다(T2-09 영역) → L2 채점에서 파서 대상 필드는 기간·주기·지역 3개로 한다.
   - 필터 판정 모델(`TableFilter`)과 질의 이해 결과(`ParsedQuery`)를 섞지 않는다. `QueryItem` 스키마는 바꾸지 않는다.
2. **규칙 파서** `parse_query(question) -> ParsedQuery`: 4자리 연도, "N년부터 M년"·"N~M년" 범위, 상대 기간("최근 N년/개월" → 주기만, 연도는 비움), 주기 표현(월별·매월 → M, 분기 → Q, 연간·매년 → Y, 5년마다·인구총조사 주기 → F), 시도 별칭 사전(서울 → 서울특별시, 강원 → 강원도·강원특별자치도 둘 다). "20년간"처럼 기간 길이를 뜻하는 표현은 연도로 보지 않는 오탐 규칙을 테스트로 고정한다. 두 자리 연도("23년")는 이번에 다루지 않는다.
3. **필터 규칙**: 연도는 1개면 strict, 2개 이상이면 partial(T2-05 측정 근거). 주기는 메타 또는 값 중 하나라도 맞으면 통과. 조건이 없으면 그 필터는 걸지 않는다.
4. **측정**: dev에서 (a) L2 필드별 정확도, (b) 필터 전후 Hit@1/5/10·MRR(벡터 KURE-v1, BM25), (c) 정답 제거율, (d) 필터가 후보를 모두 지운 문항과 사유, (e) **문항별로 얻고 잃은 내역**. test는 쓰지 않는다. 하드 필터는 이미 상위 k 밖의 정답을 끌어오지 못하므로(후보 범위만 좁힘) Hit@10 개선은 작을 수 있다.
5. **L2 골든**: 117문항의 기간·주기·지역 필드를 Claude가 초안을 쓰고, **dev 39문항은 사람이 전수 검수**한다(파서와 같은 편향으로 라벨이 붙는 순환 평가를 막기 위해). test는 초안만 두고 최종 확인 전에 검수한다.

## Option A — 기간·주기만 (원래 범위)
- 접근: `ParsedQuery`에서 기간·주기만 쓴다. 필터는 기존 `TableFilter`(연도·주기). L2는 기간·주기 2개 필드만 채점한다.
- 예상 성능 향상: L2 기간·주기 정확도 0 → 측정값(4자리 연도는 규칙으로 거의 맞음, 상대 기간·주기 표현이 관건). 검색은 연도·주기 조건이 있는 dev 문항에서 Hit@1 +1~2(근거: T2-05에서 정규식 연도 + partial 필터가 14문항 중 Hit@1 +2). 전체 29문항에서는 잡음 범위라 문항별 내역으로 판단한다. 정답 제거 0 유지가 목표.
- 실질 반영 이점: H3(기간·주기 검증이 "월별 질문에 연간 표" 오류를 줄인다)을 질문부터 끝까지 자동으로 처음 잰다. 필터가 비면 "기간·주기 불일치" 사유가 남아 T2-09 거절 문구 근거가 된다.
- 비용·리스크: 반나절 + dev 39문항 L2 검수(사람 약 20분). 멘토가 짚은 지역 조건(시도 이름 질문)은 남는다.

## Option B — A + 시도 필터 (hard·soft 비교) (멘토 Q5 반영)
- 접근: A에 시도 조건을 더한다. 표별 `regions`(그 표의 행정구역 분류에 있는 시도 정식 이름)는 레지스트리에서 계산한다. 지역 조건을 두 방식으로 나란히 잰다.
  - **hard**: 질문의 시도가 표에 없으면 후보에서 뺀다. 단 행정구역 분류가 아예 없는 표(전국 표)는 빼지 않는다(대부분이 이 경우). 개편 전후 명칭(강원도/강원특별자치도, 전라북도/전북특별자치도, 제주도/제주특별자치도)은 같은 시도로 본다.
  - **soft**: 빼지 않고, 시도가 있는 표를 순위에서 앞으로 올린다(같은 점수대 안에서 정렬). 시도가 없는 표는 사유만 기록한다.
  - 행정구역 분류 판정은 `metadata.REGION_CLASS`가 "지역"이라는 말만 있어도 걸리므로, **시도 라벨이 3개 이상인 분류만** 행정구역으로 본다(T2-25와 같은 기준).
  - `dimensions`·`measure_units`·`region_levels`와 Chroma `to_metadata` 추가는 이번에 하지 않는다. 판정은 Python 레지스트리에서 하므로 측정에 필요 없고, T2-09·T2-11에서 쓸 때 넣는다(`region_levels`는 PR #10 머지 뒤).
- 예상 성능 향상: A의 효과 + 시도 조건이 있는 dev 약 6문항에서 순위 변화. 근거가 약하다 — T2-25의 +2는 시도 이름을 **임베딩 문서에 넣은** 효과라 필터와 메커니즘이 다르다. 그래서 수치 목표 대신 "hard·soft 중 정답 제거 0이면서 Hit@1·MRR이 더 높은 쪽"을 고른다는 판정 기준을 미리 정한다.
- 실질 반영 이점: 멘토 권고(지명은 임베딩이 아니라 필터)를 측정으로 검증하고, T2-25의 "시도 이름을 임베딩에 다시 넣을지" 결정에 근거를 준다. 시도 필터의 제외 사유는 T2-09의 "분류 불일치" 거절에 그대로 쓰인다.
- 비용·리스크: 1일 + dev 39문항 L2 검수(사람 약 30분). 마감(10/31)이 지나 T2-06·T2-09와 겹친다. hard 필터가 지역 정보가 표명·기관에만 있는 표를 지울 수 있다 → 정답 제거율과 문항별 내역으로 확인한다.

## Option C — LLM 슬롯 추출 + 필터
- 접근: 규칙 파서 대신 실전 1 질의 분석(`kosis_chat/judge/question.py`, HCX structured output → `StatQuery`)을 불러 기간·지역을 뽑고 `ParsedQuery`로 바꾼다. 필터는 B와 같다. 규칙 파서와 L2 정확도를 나란히 잰다.
- 예상 성능 향상: 상대 기간·구어체 지역 표현에서 L2 정확도가 규칙보다 높을 수 있다(근거 약함). 검색 Hit@k는 B와 비슷할 것으로 본다(4자리 연도·시도 이름은 규칙으로도 거의 맞음).
- 실질 반영 이점: 종합 단계의 질의 분석과 같은 모델 경로를 미리 시험한다.
- 비용·리스크: 1.5일 + HCX 호출 117회 이상, 질의당 지연 수백 ms~수 초. 실전 1에서 JSON 1회 통과 12/29로 불안정했다. 슬롯 모델 비교(T2-16, 전민기)와 겹친다.

## Recommendation
**Option B.** 멘토가 짚은 시도 조건을 측정 없이 미루면 T2-25(시도 이름을 임베딩에 다시 넣을지)를 결정할 근거가 없다. 리뷰 반영으로 범위를 시도 필터 하나로 줄였고(분류 차원·단위·Chroma 메타데이터는 필요할 때), hard·soft를 함께 재서 정답을 지우는 위험을 수치로 본다. A는 시도 문제를 남기고, C는 효과 근거가 약하고 비용·지연이 크며 T2-16과 겹친다.
