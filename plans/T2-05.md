# T2-05 임베딩 검색 — A(표당 1벡터) + D(구조화 필터) 기준선

## Goal
- 완료 기준 (TASK.md 그대로): ChromaDB 적재(표 1건 = 문서 1건, 표 ID 보존) + 임베딩 후보 비교, 동일 골든셋으로 측정
- 기준 문서: 사용자 제공 `chromadb-ingestion-architecture-review.md`(10/29 설계 검토, 내려받기 폴더). 사용자 지시: **A(표당 1벡터) + D(구조화 필터)**로 진행. B(다중 벡터)·C(생성 질문)·BM25 결합(T2-06)·숫자 답변(T2-10)은 범위 밖.
- 이 태스크는 리뷰 문서 9장의 1~3단계다. ① A 문서 생성·적재(표 key 보존, 토큰 초과 기록, 건수 확인) ② `BaseRetriever` 연결(기존 `search_tables()` 반환 계약 유지) ③ 기간·주기 검증(실제 시점·누락 반영, 필터의 정답 제거율 측정 가능하게)
- Baseline (10/29):
  - 적재: `tables_meta_kure` 2,364문서(KURE-v1, cosine 확인, 메타데이터만, 라벨 KOSIS 코드 순). 컬렉션 이름·메타데이터에 빌드 버전 없음.
  - 검색: BM25만 `chain.search`에 연결. 벡터 검색기·기간·주기 필터 없음(`chain.py` TODO(T2-14)).
  - **검색 골든셋(T2-02)·하네스(T2-03)가 아직 없다** → "임베딩 후보 비교, 동일 골든셋으로 측정"은 이 태스크에서 끝낼 수 없다. TASK.md는 `[~]` 유지, 측정은 골든셋이 생기면 같은 코드로.

## 설계 (리뷰 문서 + 독립 리뷰 반영)
- **A 빌드**: 컬렉션 이름에 빌드 버전(`kosis_a_kure_<YYYYMMDDHHMM>`). 컬렉션 metadata에 `index_version`, 데이터(`tables.jsonl`) sha256, 문서 형식, 모델, 차원, 정규화, 거리, 문서 수를 기록한다. 문서 metadata에 `part="core"`, `index_version` 추가. 표 1개 = 문서 1개라 key 단위 집계는 필요 없다(리뷰 5.2의 집계는 B용). "active 전환"은 이번에 하지 않는다 — 공용 Chroma에 로컬 manifest를 두면 사람마다 갈라지므로, 검색기는 컬렉션 이름을 인자로 받고 빌드 기록은 컬렉션 metadata에 남긴다.
- **검색기** `ChromaTableRetriever(BaseRetriever)`: 질문 임베딩 함수는 **주입**(적재와 같은 KURE-v1, `normalize_embeddings=True`, prefix 없음). 결과는 레지스트리의 `to_document(record.info)` + `metadata["score"] = 1 − distance`. `chain.search`·`build_tools`·`TableCandidate`는 바꾸지 않는다.
- **필터(D)는 레지스트리에서 Python으로**: 2,364표뿐이라 Chroma `where`의 숫자 범위 대신, `tables.jsonl` dict로 조건에 맞는 key 집합을 만들고 Chroma에는 `where={"key": {"$in": keys}}` 한 번만 건다(후보 수가 줄어 k보다 적게 남는 문제 없음).
  - `TableFilter(years, cycle, organization, mode)`; 질문에서 이 값을 뽑는 규칙은 T2-14.
  - 연도: 실제 `periods`에 요청 연도가 **모두** 있어야 통과(`strict`, 기본). `partial`은 하나라도 있으면 통과. `start/end`가 없는 표는 연도 조건이 있을 때 제외하고 사유를 남긴다.
  - 주기: 메타 `cycle` **또는** 값의 `prd_se` 중 하나라도 맞으면 통과(`cycle_code_differs` 표를 잘못 지우지 않게).
  - 기관: 정확 일치 대신 표기 차이 사전(통계청 ↔ 국가데이터처) 포함 일치.
  - **제외 사유를 표별로 돌려준다**(`filter_tables(records, f) -> (keys, removed: {key: 사유})`). 예: "요청 2023, 실제 시점 2020까지(주기 F)". 이 정보가 T2-09·T2-14의 "기간/주기 불일치" 거절 문구 근거가 되고, 하네스는 정답 key가 `removed`에 있는지로 **정답 제거율**을 잰다.
  - 필터 전달 경로: `search_tables(question, k)` 계약은 그대로 두고, 검색기 필드 `table_filter`로 받는다(`retriever.with_filter(f)`가 복사본을 돌려줌). 스키마 변경 없음.
- **오프라인 검증 유지**: `chromadb`·`sentence_transformers`는 함수 안에서 import. 테스트는 가짜 컬렉션·가짜 임베더만.
- **거절 경로**: 필터로 후보가 0건이면 지금은 `chain.answer`가 일반 거절("찾지 못했습니다")로 끝난다. 사유 문구 연결은 T2-09·T2-14에서(이번에는 사유를 만들어 두는 데까지) — Result에 명시.

## 옵션 1 — 검색기만 (기존 컬렉션)
- 접근: `tables_meta_kure`에 검색기만 붙이고 필터 없음.
- 예상 성능 향상: 벡터 검색 경로 0 → 1. Hit@k는 골든셋 이후.
- 실질 반영 이점: `build_tools(retriever=...)` 교체 가능.
- 비용·리스크: 1~2시간. 사용자 지시(D 포함)를 채우지 못한다. 빌드 버전이 없어 다음 실험과 섞인다.

## 옵션 2 — A 빌드 버전 + 검색기 + 레지스트리 필터 (추천)
- 접근: 위 "설계" 전부.
- 예상 성능 향상: 벡터 검색 0 → 1, 필터 0 → 연도·주기·기관 3종(실제 시점 기준), 중간 시점이 빠진 표를 범위만 보고 통과시키는 오류 0(테스트), 제외 사유 표별 기록 0 → 100%. 검색 품질 수치는 골든셋 이후.
- 실질 반영 이점: 데이터 정확성(없는 연도 표를 후보에서 빼고 사유를 남김), 기술 설계(빌드 버전·기록), 재사용(T2-06·T2-07·T2-11·T2-14가 같은 검색기·필터 사용).
- 비용·리스크: 2~3시간 예상(미측정) + 재적재(직전 실측 621초). 엄격 모드가 "범위 일부만 있는 표"를 지울 수 있다 → 사유를 남기고 정답 제거율로 모드를 정한다.

## 옵션 3 — 옵션 2 + 리뷰 문서 4·5단계

- 예상 성능 향상: 종단 간 경로(미측정).
- 비용·리스크: 하루+. T2-06(전민기)·T2-10과 겹치고 사용자 지시 범위(A+D) 밖.

- 반대로 period_cycle(BM25 2~3/4 → 벡터 1/4)과 multi_condition(3/6 → 1~2/6)은 BM25가 낫다. 연도·지역 같은 정확한 단어는 BM25가 잘 잡는다 → T2-06(BM25+벡터 결합)의 근거.
- 두 빌드는 거의 같다(29문항에서 1~2문항 차이는 잡음 범위). 메모리 실험(T2-25)과 Chroma 측정 값이 같다(10/13/15, 11/12/13).
- 답 없음 판정(top-1 점수 기준값)은 네 검색기 모두 F1 0.46~0.50으로 약하다 → T2-09에서 따로 다룬다.

연도 필터(D), 답 있는 dev 중 질문에 4자리 연도가 있는 14문항. 연도는 정규식으로만 뽑았다(T2-14 규칙 대용, 주기·기관 필터는 측정 안 함).

| 빌드 | 모드 | 정답 표가 모두 지워진 문항 | Hit@1 / 5 / 10 (필터 없음 → 있음) |
| --- | --- | --- | --- |
| 라벨 나열 | strict | 2 | 1/3/5 → 2/3/4 |
| 라벨 나열 | partial | **0** | 1/3/5 → 2/4/5 |
| 1+2+3 | strict | 2 | 2/2/3 → 3/3/4 |
| 1+2+3 | partial | **0** | 2/2/3 → **4/4/5** |

- strict가 지운 2문항은 둘 다 연도가 두 개인 질문이다. 하나는 정답 표에 앞쪽 연도가 없고, 다른 하나(multi_table)는 표 두 개가 연도를 하나씩 나눠 가진다. 제외 사유에 원인이 그대로 남았다("요청 1985년 없음 (실제 2015~2023 …)").
- 따라서 기본값 strict는 연도가 여러 개인 질문에서 정답을 지운다. **연도가 2개 이상이면 partial**을 쓰는 것이 맞다 → T2-14 필터 규칙에 넘긴다(이번에 코드 기본값은 바꾸지 않았다).
- 남은 일: T2-14 질문→필터 규칙이 생기면 주기·기관 필터까지 같은 방식으로 정답 제거율을 잰다. 벡터 단독은 BM25와 강점이 갈려 결합(T2-06)이 다음 단계다.
