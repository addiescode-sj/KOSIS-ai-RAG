# T2-25 데이터 전처리 — 적재 전 표 문서 정리 방법을 하나씩 넣고 빼며 비교

## Goal
- 완료 기준 (TASK.md 그대로): 적재 전에 표 문서의 지역 라벨·항목 이름을 정리하는 방법(지역 단위 요약, 항목 이름·단위 정리, 맨 앞 요약 줄, 메뉴 경로 줄이기, 별칭, 번호 동 묶기)을 하나씩 기준 문서와 비교하고, 효과 있는 것을 팀 상의용으로 정리한다
- Linear KOS-91 (마감 10/30, 담당 임도유, Addie Lee 생성). 원래 제목 "데이터 전처리"에 TASK.md 연결용 ID를 붙여 `T2-25 데이터 전처리`로 변경(10/29, 사용자 승인).
- 사용자 지시(10/29): "한개씩 적용해보고 괜찮으면 넣고 성능이 안좋으면 빼고 다른거 적용해보고 … 최종적으로 괜찮은 것들을 알려주면 팀원들이랑 상의를 하고 정해볼게." 팀 메모 예시: 번호 동 묶기(가정1동·2동·3동 → 가정동 1,2,3), 행정구역 라벨이 길어 임베딩 때 잘릴 수 있음.
- Baseline: T2-24 적재본 `kosis_a_kure_202610291341`의 문서 형식 `meta-labels100`(표명·조사명·기관·주제·실제 기간·메뉴 경로·항목 전부·분류 라벨 분류당 100개, KOSIS 코드 순). 검색 품질 수치 없음.

### 경위 (순서가 뒤바뀐 점)
이 실험은 처음에 T2-21(문서화·Chunk·Top-K 실험) 아래에서 계획·승인·측정했다. 전처리 전용 태스크가 TASK.md에 없어 가장 가까운 T2-21에 붙였으나, 내용은 데이터 전처리라 KOS-91로 옮겼다. 계획·옵션·리뷰·사용자 선택·결과를 모두 이 파일로 옮기고, T2-21은 시작 전 상태로 되돌렸다(plan 삭제, 10/29 사용자 지시). T2-21은 원래 범위(chunk size·overlap, Top-K)로 나중에 새로 시작한다.

## 시험한 정리 방법
| # | 방법 | 바뀌는 것 |
| --- | --- | --- |
| 1 | 지역 라벨 나열 대신 단위 요약 | `행정구역별: 전국, 동부 … 외 3,467개` → `지역 단위: 전국·시도(17)·시군구(250)·읍면동(3,467)`. 단위는 Parquet의 KOSIS 코드(길이)로, 코드가 평평한 표(법무부 등)는 시도 이름 사전·분류 이름으로 판단 |
| 2 | 항목 이름 정리 | `혼인건수 (건)` → `혼인건수`, `가구_계` → `가구 계`, 기호 통일. 단위는 버리지 않고 `단위: 건, 명` 한 줄로 모음 |
| 3 | 표 구분 정보를 맨 앞 줄에 (1과 함께) | `표명 | 주기·기간 | 지역 단위 | 주요 항목`. 1+3 vs 1로 잼 |
| 4 | 메뉴 경로 줄이기 | 경로 여러 개 → 중복 단어 제거한 1줄 |
| 5 | 별칭 한 줄 | 기관 옛 이름(통계청), 영문 표명 |
| 6 | 번호 동 묶기 | `가정1동, 가정2동, 가정3동` → `가정동(1·2·3)`. 먼저 토큰 수로 효과를 재고, 잘림을 막지 못하면 변형에서 뺀다 |

**비교 방식**: 1·2·4·5는 각각 기준 문서 대비 한 번씩, 1+3은 1 대비. 좋아지는 쪽인 것만 합친 문서를 마지막에 잰다.

**판정 규칙**: 같은 질문으로 짝지어 비교. Hit@5 순증 5개 이상이고 Hit@1이 줄지 않으면 "효과 있음", 순증 1~4개는 "차이 불분명", 순감이면 "나쁨".

## 측정 방법
- 같은 모델(KURE-v1, prefix 없음, 정규화)로 문서 2,364개를 임베딩해 메모리에서 cosine 순위. 질의는 그대로. 채택 형식을 Chroma 새 빌드로 적재할 때 메모리 순위와 Chroma 순위의 일치율을 확인한다.
- 지표: Hit@1/5/10/20, MRR, 문서 평균 글자, 문항별 뒤집힘 수. 번호 동 묶기는 KURE 토크나이저 토큰 수.
- 스크립트 `scripts/doc_experiment.py` (`levels`, `answers`, `run <변형>`; 변형 이름에 `+`로 합본), 질문 `eval/search_proxy_questions.jsonl`.
