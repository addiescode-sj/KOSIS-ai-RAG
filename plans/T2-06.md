  - **벡터 KURE-v1 + T2-14 조건 필터: 14/17/18, 0.534** (1+2+3 빌드 16/17/18, 0.573) ← 지금 master 최선, 비교 기준

  - 이 골든은 실험 중 여러 번 봤으므로 탐색적이다.

## Idea
1. `src/kosis_rag/text.py`(신규): 미세조정 때 쓴 표 문서 텍스트 n2(표명·분류·항목 라벨 정규화, 라벨 60개까지)와 질의 정규화. lab `normalize_text.py`에서 추론에 필요한 부분만 옮긴다.
2. `src/kosis_rag/model.py`(신규): `load_embedder(base, ckpt)` — BAAI/bge-m3 위에 학습한 층(`.pt`)을 덮어 불러오고, GPU면 fp16. 가중치는 git에 넣지 않고 `data/models/`(gitignore)에 두며 `.env` `EMBED_CKPT`로 가리킨다.
3. `src/kosis_rag/index.py`(수정): `--model bge-m3-ft --ckpt <pt> --doc-format n2` 옵션으로 별도 컬렉션(`kosis_a_bgeft_<버전>`)을 적재한다. 메타데이터(`to_metadata`)는 기존과 같게 넣어 T2-14 필터가 그대로 동작한다. 기존 KURE 경로·기본값은 그대로.
4. `ChromaTableRetriever.connect`(수정): 컬렉션 메타데이터의 `embed_model`·`doc_format`·`ckpt`로 질의 임베더를 고른다(지금은 KURE가 아니면 거부). 둘이 다르면 지금처럼 거부한다.
5. `src/kosis_rag/retriever.py`(수정): `HybridRetriever(retrievers, k_each=50, c=60)` — 각 검색기 상위 50을 표 키로 RRF 합산, 동점은 먼저 나온 순서. 순서만 RRF로 정하고, **`metadata["score"]`는 dense 코사인을 그대로 둔다**(RRF 값은 1/61~2/61 좁은 범위라 T2-09 답 없음 임계값에 못 씀). BM25에서만 나온 표는 dense 상위 50의 최저 코사인을 넣고 `score_from="bm25"`를 표시한다. `rrf_score`와 검색기별 순위는 따로 남긴다. BM25는 n2 텍스트로 만든 것을 쓴다(lab과 같음).
6. 측정: `evals/runners/retrieval.build`에 `hybrid-ft`(미세조정 dense + BM25 n2), `hybrid-ft+cond`(C), `hybrid-kure`(A) 이름을 추가해 같은 dev 29로 잰다. 공식 측정은 평가 엔지니어링(이선주) 담당이라 수치는 참고값으로 `## Result`에 적는다.
7. 가중치: 배포용은 **seen-e2**(전체 표의 합성 질문으로 학습, 11/02 결정). 골든 정답 표의 합성 질문(골든 문항 자체는 아님)이 학습에 들어갔으므로 seen-e2의 골든 수치는 Result·TASK.md에 항상 "낙관적"으로 표시한다. 공정한 추정은 unseen-e1이며, 두 가중치를 같은 dev로 나란히 잰다.
8. T2-29(슬롯 → 필터 → 하이브리드, KOS-103)는 이 `HybridRetriever`를 그대로 쓴다(하이브리드를 두 번 만들지 않는다).

## Option A — KURE 하이브리드 (새 모델 없음)
- 접근: 지금 master 컬렉션(KURE-v1, T2-27 문서 형식) + BM25 전체 라벨을 `HybridRetriever`로 RRF. `text.py`·`model.py`·새 컬렉션 없음.
- 예상 성능 향상: dev Hit@5 13 → 14~15 정도(근거 약함: 두 검색기의 dev Hit@10 정답 집합이 일부만 겹친다는 점뿐, lab에서 KURE 하이브리드를 검색 골든으로 잰 값은 없음). 필터 없이는 KURE + 필터(14/17/18)를 넘기 어렵다.
- 실질 반영 이점: TASK 완료 기준(하이브리드 측정)을 가장 빨리 채운다.
- 비용·리스크: 반나절. 미세조정 결과(계획 29·43)가 master에 안 들어가고, T2-07의 학습된 리랭커는 미세조정 하이브리드 상위 50으로 학습되어 입력 분포가 다르다.

## Option B — 미세조정 bge-m3(n2 컬렉션) + BM25 n2, RRF (lab F0 이식)
- 접근: Idea 1~7, 조건 필터 없음.
- 예상 성능 향상: lab F0 89문항 Hit@1 0.416 / Hit@5 0.607을 dev 29에 비례하면 약 12/18 (dev 실측 아님). **필터 있는 master 최선(14/17/18)보다 Hit@1이 낮을 수 있다.** seen-e2는 더 높게 나올 수 있으나 낙관적.
- 실질 반영 이점: 실험에서 가장 효과가 컸던 임베딩 미세조정을 서비스 경로에 넣고, T2-07 리랭커와 입력 분포가 같다. 모델 로딩(`model.py`)·문서 텍스트(`text.py`)가 분리되어 Phase 3에서 모델만 바꿔 끼운다.
- 비용·리스크: 1일. 컬렉션 적재 1회(2,364표, GPU 수 분). 가중치 약 400MB를 팀원에게 전달(Drive). Docker에 bge-m3 기본 모델 다운로드 추가. **문서 형식이 둘(n2 / T2-27)이 되어 관리 경로가 늘어난다.**

## Option C — B + 기존 T2-14 조건 필터를 dense 쪽 앞에 (추천)
- 접근: B에 `parse_query` → `TableFilter`를 붙인다. dense는 `ChromaTableRetriever.with_filter`(k=50, 상한 없음, `soft_rank` 포함)로 거른 뒤 검색하고, BM25는 상위 후보를 같은 `filter_tables` 규칙으로 거른다. `ConditionRetriever`(상위 10 상한)는 쓰지 않는다. 새 점수 가산(lab β·γ)은 넣지 않는다. 필터는 `.env` `COND_FILTER=on|off`로 켜고 끈다.
- 예상 성능 향상: dev Hit@1 14(KURE + 필터) 이상을 목표로 한다(근거: KURE에서 필터가 Hit@1 +4, lab에서 미세조정 하이브리드에 연도·지역 조건을 더하면 89문항 Hit@5 0.607 → 0.652). 미세조정 + T2-14 필터 조합은 미측정.
- 실질 반영 이점: master 최선(필터)을 잃지 않으면서 미세조정을 넣는다. 새 코드 없이 T2-14 필터를 재사용하고, 거절 사유(`last_removed`)가 그대로 T2-09로 간다.
- 비용·리스크: B + 반나절. T2-29(KOS-103)와 범위가 일부 겹친다 → T2-29는 이 조합에 슬롯 추출기(`QuerySlots`)만 바꿔 끼우는 것으로 줄어든다(TASK.md에 적음).

## Recommendation
**Option C.** B만 넣으면 지금 master 최선(KURE + 필터 Hit@1 14)보다 낮아질 수 있다. 필터는 이미 있는 `with_filter`를 쓰므로 비용이 작고, on/off로 B도 같이 잰다. A는 미세조정 효과를 버리고 리랭커와 입력 분포가 맞지 않는다.
