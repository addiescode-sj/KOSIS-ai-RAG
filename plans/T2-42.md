## Idea
1. 키 후보 정하기: 전체 미매핑 314개에서 빈도 2 이상인 실제 분류명을 고른다. 하나씩 기존 키와의 충돌을 확인한다(예: '세대'는 단위 '세대'와 겹치고, '거주지'는 부분 문자열로 현거주지와 맞고, '년생'은 연령과 겹친다).
2. 새 키를 질문 쪽에도 열지 결정한다. 새 키가 `DIMENSION_WORDS`에 들어가면 파서(`parse/patterns.py` `_DIM_WORD`)가 새 hard 분류 필터를 만들 수 있다(리뷰 5). 그래서 **충돌 위험이 있는 키는 표 쪽만**(`_QUESTION_SKIP`) 두고, 질문 쪽에는 명확한 키만 연다.
3. 옵션별 구현(아래). 비자명한 규칙마다 pytest를 둔다.
4. 측정
   - L0: 전체·정답 표, 분모 고정 미매핑 개수(주)와 비율(보조)
   - L2: v1·v2 dimensions P/R (선행 조건 1)
   - L1: `hybrid+cond` test 전→후 Hit@1·Hit@5. 필터는 `table_roles`·`has_dimension`을 검색할 때 바로 쓰므로 필수 점검이다(리뷰 5)
5. 색인
   - 확인함(코드): 분류 필터는 검색할 때 `tables.jsonl` 레코드에서 바로 계산한다. 서비스 임베딩 문장 n2-L60에는 분류 이름이 들어가지 않는다(분류는 폐기된 n3에만 들어감). 그래서 **검색에는 재적재 없이 반영**된다.
   - Chroma 메타데이터 `f_dims`에는 옛 값이 남는다(검색 코드에서는 읽지 않음). KOS-118의 "새 빌드 적재"는 같은 벡터로 메타데이터만 다시 쓴 새 컬렉션을 만드는 일이다. 기존 컬렉션은 지우지 않는다.

## Option A — 사전·이름 규칙 보강 (③·④)
- 접근: `vocab._KEY_GROUPS`에 ③의 키 약 15개를 더한다(충돌 위험 키는 표 쪽만). `dimension_keys`에 "X별 Y 여부" 규칙(앞의 X만 키로)을 넣는다. 묶음 분류는 건드리지 않는다.
- 예상 성능 향상 (분모 고정)
  - 전체 미매핑 314 → 약 250개 (0.046 → 약 0.037)
  - 정답 표 195 → 약 175개 (0.401 → 약 0.36)
  - 근거: ③ 약 60개 + ④ 일부. 정답 표는 ③ 약 20개뿐이다.
  - L2 dimensions R: 질문 쪽에 연 키만큼 소폭 오른다. 새 hard 필터로 P가 떨어질 위험은 L2·L1로 확인한다.
- 실질 반영 이점: 바뀌는 곳이 사전 하나라 위험이 가장 작다. 정답 표에 쏠리지 않은 전체 메타데이터 품질 개선이다.
- 비용·리스크: 반나절. 정답 표 미매핑의 대부분(사할린 조사)은 그대로 남는다.

## Option B — A + 묶음 분류를 라벨 블록으로 나눠 dimensions에 넣기 (①)
- 접근: A에 더해, '특성별'의 라벨을 블록 사전(남성·여성 → 성, '\d세대' → 이주세대, 'F-\d' → 체류자격, 학교급 → 교육정도, 'N년 미만' → 거주기간, 출생지역·국적·주택유형)으로 읽어 실제 분류 이름 여럿으로 바꾼다. 라벨 사전은 전체 119표의 라벨 빈도로 정한다. '기본항목'(라벨이 단위 괄호를 단 측정 항목)은 분류에서 빼서 "재분류"로 따로 센다. 규칙은 `roles.table_roles`의 분류 목록 끝 단계 한 곳에 둔다.
  - 나눈 블록 사이는 주변합이므로, 두 블록을 함께 요구하는 필터(성 + 이주세대)는 이 표에서 통과시키지 않는다. 이를 위해 `fields`에 "주변합 묶음" 표시를 둔다(pytest).
  - 새 키 '이주세대'·'주택유형'은 질문 쪽 키가 있어야 L0에서 매핑으로 잡힌다(리뷰 2). '이주세대'는 '세대'와 철자를 분리해 단위와 겹치지 않게 한다.
- 예상 성능 향상 (분모 고정: 원래 '특성별' 이름 하나에서 블록 하나라도 매핑되면 매핑으로 셈)
  - 전체 314 → 약 145개 (0.046 → 약 0.021)
  - 정답 표 195 → 약 90~110개 (0.401 → 약 0.19~0.22)
  - 근거: A에 더해 ① '특성별' 99개(정답 81개). '기본항목' 5개는 재분류로 따로 적는다. 분모가 바뀌는 보조 비율(정답 표 약 0.10~0.15)은 주 지표로 쓰지 않는다(리뷰 3).
- 실질 반영 이점: 정답 표의 36%를 차지하는 사할린 표에서 성·체류자격·교육정도 같은 단일 분류 필터가 처음으로 맞을 수 있다(데이터 정확성). 주변합 표시로 과대 매칭은 막는다.
- 비용·리스크: 1~1.5일. 라벨 블록 추론이 다른 조사의 '특성별'(사할린 외 18개)을 잘못 나눌 수 있다. 전체 119표를 표본 검수한다. `table_roles` 변경은 필터에 바로 반영되므로 L1 점검이 필수다.

## Option C — A + 묶음 분류를 dimensions 대신 implied_keys로 (필터만)
- 접근: A에 더해, '특성별' 블록에서 읽은 분류를 `fields.implied()`의 implied_keys로 넣는다(리뷰 1의 대안). dimensions와 L0 정의는 그대로 두고 필터(`lacks_role`)에만 반영한다.
- 예상 성능 향상: L0 미매핑은 A와 같다(implied_keys는 `mapped_dimension`이 보지 않음). 필터 쪽 효과(사할린 단일 분류 질문)는 B와 비슷하다.
- 실질 반영 이점: 표의 분류 목록(dimensions)과 L0 정의를 건드리지 않아 가장 보수적이다. 기존 implied 경로(성·혼인상태·가구원수를 항목 이름에서 읽는 KOS-109 방식)를 그대로 따른다.
- 비용·리스크: 1일. KOS-118 완료 조건인 "L0 미매핑 전→후"에서는 A 이상의 개선이 보이지 않는다. 지표에 안 보이는 개선을 따로 설명해야 한다.

## Recommendation
**Option B.** KOS-118의 목표인 "분류 이름이 질문 분류 어휘로 매핑되는가"를 정면으로 개선하고, 분모를 고정한 개수로도 정답 표 195 → 약 100개의 개선이 보인다. 주변합 표시로 과대 매칭을 막고, 전체 범위를 주 지표로 써서 정답 표 쏠림을 피한다. C는 같은 필터 효과를 더 보수적으로 얻지만 완료 조건 지표에 나타나지 않는다. ② 설문 응답 분류(약 90개)는 이번에 빼지 않는다. 결과표에 "분류가 아닌 설문 응답"으로 따로 적는다.
