# 초대형 표 청킹 기준 (T2-43, KOS-179)

대상은 제공 데이터에서 행이 가장 많은 두 표다. 둘 다 행정안전부 「주민등록인구현황」이다.

| | `101_DT_1B04005N` | `101_DT_1B04006` |
|---|---|---|
| 표 이름 | 행정구역(읍면동)별/5세별 주민등록인구(2011년~) | 행정구역(시군구)별/1세별 주민등록인구 |
| 행 수 | 47,225,151 | 21,129,606 |
| 지역 | 4,813곳 (전국·시도 19, 시군구 310, 읍면동 4,484) | 345곳 (전국·시도 19, 시군구 326) |
| 시점 | 월 201207~202609 (171개), 년 2011~2025 (15개) | 월 200801~202609 (225개), 년 2008~2025 (18개) |
| 연령 | 22구간 (계 + 5세 단위) | 102구간 (계 + 1세 단위) |
| 항목 | 총인구수, 남자인구수, 여자인구수 (명) | 같음 |

## 기준: 표의 지역 1곳 = 청크 1개

1. **청크 단위는 지역 코드다.** 두 표는 지역 × 연령 × 항목 × 시점으로만 이루어져 있고, 연령·항목은 모든 지역에서 같다.
   질문이 이 표의 한 부분을 가리킬 때 쓰는 것은 지역 이름이고, 지역마다 실제로 다른 정보는 수록 기간뿐이다
   (동이 신설·폐지·통합되어 `1B04005N`의 1,832곳, `1B04006`의 114곳은 일부 기간만 있다).
2. **청크 본문에 값을 넣지 않는다.** 숫자는 임베딩에 뜻이 실리지 않고, 값은 Parquet에서 코드가 읽는다
   (CLAUDE.md "숫자는 코드가 계산"). 본문에는 지역 경로, 표 이름, 그 지역의 실제 수록 기간, 연령 구분, 항목·단위, 조사명만 쓴다.
3. **청크에서 원본 행으로 돌아가는 길은 메타데이터의 지역 코드 하나다.**
   `kosis_rag_build.chunks.read_chunk_rows(parquet, meta)`가 `dim1_code = region_code` 필터로 읽는다.
4. **청크는 원본 행을 빠짐없이 한 번씩 덮는다.** `(지역, 시점, 연령, 항목)`이 겹치는 행이 있으면 만들기를 멈추고,
   청크 행 수 합이 `tables.jsonl`의 행 수와 다르면 적재하지 않는다.
5. **표 색인과 섞지 않는다.** 청크는 `kosis_chunks__region1__<해시>` 컬렉션에 따로 둔다. 검색이 읽는 표 색인
   (`kosis_kure__…`, 표 1건 = 문서 1건)은 그대로다. 해시는 두 Parquet 파일 내용에서 나오므로 월 자료가 갱신되면
   새 컬렉션이 생기고 옛 컬렉션은 남는다.

본문 예:

```
경기도 의정부시 고산동 | 행정구역(읍면동)별/5세별 주민등록인구(2011년~) | 지역: 경기도 > 의정부시 > 고산동 (읍면동) | 수록기간: 월 202407~202609, 년 2024~2025 | 5세별: 계, 0 - 4세, 5 - 9세, 10 - 14세 외 18개 | 항목: 총인구수, 남자인구수, 여자인구수 (명) | 조사명: 주민등록인구현황
```

## 지역 등록부와 메타데이터

`data/chunks/regions.jsonl`(gitignore)이 먼저 만들어지고, Chroma 청크는 이 파일 1줄 = 1개다. 임베딩 없이 지역 이름
정확 일치로 코드를 찾는 데에도 쓸 수 있다.

| 메타데이터 | 뜻 |
|---|---|
| `key`, `org_id`, `tbl_id`, `table_name`, `survey_name`, `organization`, `period`, `url` | 표 색인과 같은 표 정보. 청크 검색 결과도 `shared.catalog.to_candidate`로 바로 표 후보가 된다 |
| `part` | `region` (표 색인 문서는 `core`) |
| `region_code`, `region_label`, `region_level`, `region_path`, `parent_code` | 지역 코드, 이름, 단위(전국·시도·시군구·읍면동), 경로, 가장 가까운 상위 코드 |
| `start_m`, `end_m`, `n_m` / `start_y`, `end_y`, `n_y` | 주기별 첫 시점·끝 시점(정수)·시점 수. 범위 필터용 |
| `missing_m`, `missing_y` | 첫 시점과 끝 시점 사이에서 그 지역에 없는 시점 목록. 있을 때만 |
| `rows`, `value_rows` | 그 지역의 행 수, 값이 있는 행 수 |

청크 id는 `<표 키>|<지역 코드>`다(예: `101_DT_1B04005N|4115062000`). 다시 적재하면 같은 id에 덮어쓴다.

- 지역 단위는 코드 길이로 정한다: `00` 전국, 2자리 시도, 5자리 시군구, 10자리 읍면동.
- 경로는 표에 상위 코드가 있을 때만 붙는다. `1B04005N`의 읍면동 5곳은 시도 코드가, 18곳은 시군구 코드가 표에 없어
  (행정구역 개편 전 옛 코드) 경로가 짧다.
- 한 코드에 라벨이 둘이면 만들기를 멈춘다(지금 데이터에서는 0건).

## 만들기

```bash
PYTHONPATH=.:src python -m kosis_rag_build.cli chunks --data-dir <제공 데이터 폴더>            # 등록부 + Chroma 적재
PYTHONPATH=.:src python -m kosis_rag_build.cli chunks --data-dir <제공 데이터 폴더> --registry-only   # 등록부만
```

`--table <표 키>`를 반복해 다른 표를 지정할 수 있다. 단, dim1이 행정구역이고 dim2가 다른 분류 하나인 표만 맞는다.

## 검토하고 고르지 않은 기준

| 기준 | 청크 수 | 고르지 않은 까닭 |
|---|---|---|
| 상위 지역 묶음 (시군구마다 읍면동 이름 나열) | 323 | 실측에서 `1B04006`이 지금보다 나빠졌다(전체 경로 질문 54 → 19). 읍면동별 수록 기간을 담지 못한다 |
| 등록부만, 정확 일치 (임베딩 없음) | — | 이름이 같은 지역(표본 100곳 중 25~36곳)은 하나로 정해지지 않고, 줄임말에는 별칭 사전이 따로 필요하다 |
| 지역 × 기간 값 청크 | 약 12만 7천 | 임베딩 약 17시간, 숫자를 본문에 넣어 원칙과 어긋난다 |
| 원본 행 그대로 | 6,835만 | T2-24 실측: 전체 표 기준 약 72일 · 47GB |

실측 수치와 측정 방법은 `plans/T2-43.md`.

## 한계

- 검색 그래프는 아직 이 컬렉션을 읽지 않는다. 연결 전에는 챗봇 답이 바뀌지 않는다(AI 파이프라인 담당 범위).
- 두 표는 같은 시군구 326곳을 모두 갖는다. 질문에 "5세별"·"1세별"처럼 연령 단위가 드러나지 않으면 청크만으로 두 표를
  가를 수 없다. 연령 단위 슬롯으로 걸러야 한다.
- 이름이 같은 지역(중구, 서구, 동면 등)은 상위 지역 없이 물으면 틀린 지역이 1위가 될 수 있다.
- 지역 이름 질문이 아닌 질문(연령·기간만 묻는 질문)에는 도움이 없다. 표 색인이 맡는다.
