# T2-09 답 없음 판정: HCX-007 LLM 리랭커 적용 전후와 thinking none / low 비교

2026-11-02 · 이선주 · plan: [plans/T2-09.md](../../plans/T2-09.md) (옵션 A 선택형)

## 요약

리랭커 없음, 즉 점수 임계값 τ만 쓰는 판정과 비교한 결과다. 하이브리드 상위 20개 위에 HCX-007 2차 리랭커를 얹고 "고른 표가 0개면 답 없음"으로 판정했다. thinking low와 프롬프트 v2 조합에서 **test 답 없음 F1이 0.474에서 0.882로 올랐다.** 같은 설정에서 **Hit@1은 19에서 33(/60), MRR은 0.399에서 0.608로 올랐다.** 답이 있는 질문을 잘못 거절한 경우는 40/60에서 1/60으로 줄었다. 대가는 지연이다. p50이 0.09초에서 10.9초로 늘었다.

| test 78문항 (답 있음 60 · 없음 18) | 답 없음 F1 | P / R | 답 있음 오거절 | Hit@1 | MRR | 지연 p50 / p95 |
| --- | --- | --- | --- | --- | --- | --- |
| 리랭커 없음 (τ) | 0.474 | 0.310 / 1.000 | 40/60 | 19 | 0.399 | 0.09 / 0.41 s |
| HCX-007 · thinking none · v2 | 0.692 | 0.529 / 1.000 | 16/60 | 27 | 0.518 | 1.6 / 52.5 s |
| **HCX-007 · thinking low · v2** | **0.882** | **0.938 / 0.833** | **1/60** | **33** | **0.608** | 10.9 / 31.4 s |

thinking low는 none보다 F1이 +0.19, Hit@1이 +6 높다. 그 대신 지연 p50이 약 7배, 출력 토큰이 약 20배다(질문당 28 → 578).

## 실험 설정

- **1단계 (모든 설정 공통):** `hybrid+cond`는 KURE-v1 Chroma 컬렉션 `kosis_a_kure_202610301530`, BM25, RRF, T2-14 조건 필터로 이루어진다. 이 PC에는 미세조정 가중치(`data/models/`)가 없어서 T2-06/T2-07의 n2 미세조정 모델 수치(dev MRR 0.551~0.656)보다 1단계가 약하다. 전후 비교는 같은 1단계 위에서 했으므로 차이 자체는 유효하다.
- **2단계:** `LLMReranker`(T2-07)에 `LLM_RERANKERS["hcx"]`를 연결했다(`src/kosis_rag/hcx.py`). HCX-007은 상위 20개 표의 n3 카드(표당 약 500자)를 보고 `{"picked": [번호], "reason": ...}`를 낸다. 고른 표를 앞으로 보내고 나머지는 1단계 순서를 유지한다. 표 ID는 입력 번호로만 되찾으므로 LLM이 표 ID를 지어낼 수 없다.
- **판정 규칙 (같은 실행 안에서 함께 채점):**
  - `tau`: 1단계 1위 점수 < τ. τ는 dev에서 F1이 최대가 되게 고른다.
  - `llm`: 고른 표 0개. 호출 오류는 판정에서 뺀다.
  - `either`: `tau`와 `llm` 중 하나라도 해당하면 답 없음.
- **τ 공정성 수정:** 원래 러너는 재정렬 뒤의 1위 점수를 썼다. 이를 `stage2_input_top_score`(1단계 1위 점수)로 바꿨다. 그래서 모든 설정의 `tau` 행이 리랭커 없음과 같은 값을 보인다.
- **골든셋:** `evals/datasets/retrieval_golden.jsonl`. dev 39문항(답 없음 10)으로 프롬프트를 고르고, test 78문항(답 없음 18)을 공식 수치로 쓴다.
- **실행:** 아래 명령을 설정마다 1회씩, 117문항 전부에 대해 돌렸다.

  ```
  CHROMA_COLLECTION=... HCX_THINKING=none|low python -m evals.run_eval --layer l1 --retriever hybrid+cond-hcx --split all
  ```

  표는 `compare.py`가 결과 파일 `results.jsonl`에서 split별로 다시 계산한다. 전체 출력은 [compare_output.md](compare_output.md)에 있다.

## 결과

### 1. 리랭커 적용 전후 (`llm` 규칙)

| 설정 | dev F1 | test F1 | test 오거절 | test Hit@1 / @5 / @10 | test MRR |
| --- | --- | --- | --- | --- | --- |
| 리랭커 없음 (τ) | 0.488 | 0.474 | 40/60 | 19 / 29 / 39 | 0.399 |
| v1 · none | 0.500 | 0.507 | 32/60 | 24 / 31 / 40 | 0.469 |
| v1 · low | 0.727 | 0.732 | 8/60 | 29 / 40 / 43 | 0.556 |
| v2 · none | 0.621 | 0.692 | 16/60 | 27 / 35 / 43 | 0.518 |
| v2 · low | **0.762** | **0.882** | **1/60** | **33 / 41 / 44** | **0.608** |

- **τ는 이 1단계에서 판정 신호가 되지 못한다.** dev에서 F1이 최대인 τ도 답 있는 질문의 2/3를 거절한다(40/60). KURE 코사인은 답 있음과 답 없음의 분포가 겹친다. T2-07 기록(n2 미세조정 가중치)의 F1 0.737~0.750과 비교하면 1단계 모델 차이가 크다.
- **2차는 검색 순위도 올린다.** 상위 20개 안에 있던 정답 표를 LLM이 앞으로 올려서 Hit@1이 19에서 33, Hit@10이 39에서 44가 됐다. Hit@10이 오른 것은 11~20위에 있던 정답이 올라왔기 때문이다.
- **`either` 규칙(τ 또는 llm)은 모든 설정에서 `llm` 단독보다 나빴다.** test F1이 0.44~0.47이다. τ 쪽의 과거절이 그대로 더해지기 때문이다. 이 1단계에서는 τ를 결합하지 않는다.

### 2. thinking none vs low

| test (v2 프롬프트) | none | low | 차이 |
| --- | --- | --- | --- |
| 답 없음 F1 | 0.692 | 0.882 | +0.190 |
| 답 없음 Precision / Recall | 0.529 / 1.000 | 0.938 / 0.833 | 과거절 → 균형 |
| 답 있음 오거절 | 16/60 | 1/60 | −15 |
| Hit@1 / MRR | 27 / 0.518 | 33 / 0.608 | +6 / +0.090 |
| 지연 p50 / p95 | 1.6 / 52.5 s | 10.9 / 31.4 s | p50 약 7배 |
| 질문당 입력 / 출력 토큰 (117문항 평균) | 5,923 / 28 | 5,923 / 578 | 출력 약 20배 |
| HCX 호출 (78문항, 재시도 포함) | 117 | 106 | — |

- **none은 지나치게 엄격하다.** v1 프롬프트에서 1위가 정답 표인데도 거절한 질문이 있었다("주민등록 총인구수", "출산율 알려줘"). 정답 표가 상위 10위 안에 있었는데 거절한 경우가 19건이었다. 생각 없이 "직접 담은 표만" 규칙을 문자 그대로 적용한 결과로 보인다.
- **low는 질문의 지표와 표의 세는 대상을 맞춰 보고 고른다.** 오거절은 1건("서울 사람 몇 명이야?")뿐이다. 놓친 답 없음 3건은 "시도별 대학 진학률", "청년 고용률 추이", "2027년 1월 출생아 수"다. 앞의 두 건은 비슷한 인구 표를 고른 경우이고, 마지막 건은 미래 기간이라 T2-14 필터가 잡을 몫이다.
- **none의 p95 52초는 모델 시간이 아니라 재시도 대기다.** 78문항에 HCX 호출이 117번 있었다. 429/5xx 재시도(5·15·30초 대기, Phase 1 `HCXClient`)가 꼬리를 만들었다. low는 호출 간격이 길어서 재시도가 적었다.

### 3. 프롬프트 v1 → v2 (dev로 고름)

v1은 "질문이 묻는 수치를 직접 찾을 수 있는 표만, 주제만 비슷한 표는 고르지 말 것"이었다([prompt_v1.txt](prompt_v1.txt)). dev 오류를 보면 연도·지역 세부 단위가 있는 질문을 거절하는 경우가 많았다. 그래서 v2는 "질문이 묻는 **통계 지표**를 담은 표면 고르고, 연도·주기·세부 지역은 코드가 확인하니 판단하지 말 것"으로 바꿨다(`src/kosis_rag/hcx.py` `SYSTEM`). 결과는 다음과 같다.

- dev F1: none 0.500 → 0.621, low 0.727 → 0.762
- test F1: none 0.507 → 0.692, low 0.732 → 0.882

test는 v2를 고른 뒤에 한 번만 쟀다.

### 4. 거절 사유 라벨은 믿기 어렵다

v2·low에서 답 없음으로 맞게 거절한 문항의 골든 사유와 LLM 사유를 비교했다(dev+test).

| 골든 \ LLM | no_item | out_of_scope | null |
| --- | --- | --- | --- |
| out_of_scope (13) | 9 | 1 | 3 |
| no_period (6) | 4 | 0 | 2 |
| no_item (4) | 2 | 0 | 2 |

HCX-007은 "자동차 등록 대수"나 "소득 5분위" 같은 범위 밖 질문을 대부분 `no_item`으로 붙였다. 그래서 서비스 안내 문구는 `out_of_scope`일 때만 전용 문장을 쓰고, 나머지는 일반 거절 문장(`REFUSAL_TEXT`)을 쓴다(`src/kosis_rag/chain.py` `REFUSALS`). 판정(답 없음 여부)은 믿을 만하지만 사유는 아니다.

## 효과 정리 ("무엇을 바꿔서 몇 → 몇")

- HCX-007 2차 리랭커(thinking low, 프롬프트 v2)를 붙여 test 기준으로 다음이 바뀌었다.
  - 답 없음 F1: 0.474 → 0.882
  - 답 있음 오거절: 40 → 1
  - Hit@1: 19 → 33
  - MRR: 0.399 → 0.608
- 같은 리랭커에서 thinking을 none에서 low로 바꾸자 F1이 0.692 → 0.882, Hit@1이 27 → 33으로 올랐다. 대가로 지연 p50이 1.6 → 10.9초, 출력 토큰이 약 20배로 늘었다.
- 프롬프트를 v1에서 v2로 바꾸자(지표만 판단하고 기간·지역은 코드에 맡김) test F1이 low 기준 0.732 → 0.882로 올랐다.

## 한계와 주의

- **1단계가 서비스 기본(n2/n3 미세조정 + 1차 bge 리랭커)과 다르다.** 미세조정 1단계에서는 τ 기준선이 더 강하다(T2-07 기록 F1 0.737~0.750). 그래서 F1 상승 폭은 여기보다 작을 수 있다. 가중치가 있는 환경에서 `staged-hcx`로 다시 재야 한다.
- **문항 수가 작다.** test 답 없음은 18문항이라 1문항이 recall 0.056에 해당한다. 프롬프트와 thinking 설정은 dev(답 없음 10문항)로 골랐다.
- **설정마다 1회만 실행했다(temperature 0).** HCX 응답의 반복 간 변동은 재지 않았다.
- **v1-low 첫 실행은 버렸다.** 실행 도중 네트워크 DNS 장애로 117문항 중 53문항의 호출이 실패해서(`evals/reports/20261102-175044-...`) 다시 측정했다. 위 표의 v1-low는 재측정값이다.
- **JSON 파싱:** v1-none에서 1건이 JSON 객체를 두 번 출력해 실패했다. 이후 파서를 첫 객체만 읽도록 고쳤다(`hcx.parse`, pytest 포함).
- **비용:** `evals/pricing.json`에 HCX-007 단가가 비어 있어 원화 비용은 계산하지 않았다. 토큰 수로만 비교했다.

## 채택 제안

- **정확도 우선(발표·평가 수치):** `STAGE2=hcx HCX_THINKING=low`. 답 없음 F1과 Hit@1이 모두 가장 좋다.
- **응답 속도 우선(데모 채팅):** p50 11초가 부담이면 `HCX_THINKING=none`(p50 1.6초)도 리랭커 없음보다 F1 +0.22, Hit@1 +8 낫다. 다만 오거절이 16/60이다.
- **다음 단계:**
  - 미세조정 가중치 환경에서 `staged-hcx`를 다시 잰다.
  - 미래 기간 질문(2027년 등)을 T2-14 필터로 거절한다.
