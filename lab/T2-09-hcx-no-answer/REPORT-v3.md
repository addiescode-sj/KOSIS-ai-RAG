# T2-09 HCX 프롬프트 v3 측정 — thinking none vs low

- 일시: 2026-11-03 · 브랜치 `T2-09-hcx-prompt-v3` (b3f9d12, `PROMPT_VERSION = "v3"`)
- 설정: `hybrid+cond-hcx` (KURE hybrid + T2-14 조건 필터 → HCX-007 선택형 리랭커 top 20), `--split all`
- 골든셋: `evals/datasets/retrieval_golden.jsonl` (sha256 e041d9ba…), dev 39문항(답 없음 10) · test 78문항(답 없음 18)
- 비교 대상: 어제 측정한 base(LLM 없음) · v2-none · v2-low (같은 골든셋·컬렉션)
- 결과 폴더: `evals/reports/20261103-121019-T2-09-hcx-v3-think-none`, `evals/reports/20261103-133304-T2-09-hcx-v3-think-low`

## 1. 결론

1. **v3는 thinking none을 크게 끌어올렸다.** test에서 llm 규칙 F1 0.692 → 0.813 (호출 오류 3건 제외 시 0.867),
   답 있는 질문 오거절 16/60 → 1/60, Hit@1 27 → 29.
2. **v3는 thinking low를 오히려 떨어뜨렸다.** test에서 F1 0.882 → 0.743, 오거절 1/60 → 4/60, Hit@1 33 → 30.
3. **v3 안에서는 none ≥ low.** test F1 0.813 vs 0.743, dev 0.696 vs 0.727(비슷). 출력 토큰은 none이 1/18,
   1회 호출 지연은 1.6 s vs 8.8 s.
4. **전체 최고는 여전히 v2-low** (test F1 0.882, Hit@1 33). 다만 **v3-none**이 그 F1에 근접하고(0.81~0.87),
   지연은 약 1/6이다. 서비스 기본값 후보로는 **v3-none**을 권장한다. dev 기준으로 정하면 v2-low(0.762)가
   v3-none(0.696)보다 높으므로, 채택하려면 재측정으로 확인해야 한다(§5).

`either`(τ 또는 llm) 규칙은 v2와 마찬가지로 τ의 오거절을 그대로 물려받아 F1 0.47 안팎이므로 쓰지 않는다.

거절 사유 일치(HCX가 붙인 out_of_scope/no_item과 골든 사유)는 v3-none 3/8(dev)·3/13(test),
v3-low 2/8·4/13이다. v2(1~2건)보다 조금 낫지만 여전히 낮아서, 서비스에서는 계속 out_of_scope만
별도 문구로 쓴다.

## 4. 비용·지연

| 설정 | 1회 호출 지연 p50 / p95 | 출력 토큰 평균 | 입력 토큰 평균 | 1회에 끝난 문항 |
| --- | --- | --- | --- | --- |
| v2-none | 1.54 / 2.14 s | 29 | 5,912 | 104/117 |
| v2-low | 9.83 / 15.58 s | 575 | 5,776 | 99/117 |
| v3-none | 1.58 / 3.91 s | 28 | 6,223 | 93/117 |
| v3-low | 8.82 / 15.03 s | 491 | 6,050 | 42/117 |

v3 측정 중 HCX API에서 **429 rate limit**이 많이 났다. 특히 low 실행에서는 72/117 문항이 재시도 3회
(5+15+30 s 대기)를 거쳤다. 그래서 전체 지연(v3-low p50 57 s, LLM 호출 338회)은 모델 성능이 아니라 재시도
대기 시간이다. 위 표는 재시도 없이 한 번에 끝난 문항만 모았다. v3 프롬프트는 입력이 약 300 토큰 늘었고,
지연은 v2와 같은 수준이다.

## 5. 한계

- 1회 측정이다. dev의 답 없음은 10문항뿐이라 1문항이 F1을 0.03~0.05 움직인다. none↔low 차이 중
  dev에서 난 것(0.696 vs 0.727)은 노이즈 범위다.
- 429 오류가 v3-none 4건, v3-low 1건 있었다. 오류 문항은 "답 있음"으로 처리되어 recall을 깎는다.
  v3-none test의 R 0.722 → 0.812(오류 제외)가 그 영향이다.
- v3는 dev 측정 없이 작성된 프롬프트다. v2는 dev로 골랐다. 공정하게 비교하려면 rate limit이 없을 때
  v2-low와 v3-none을 같은 시간대에 다시 돌려야 한다.
- 파인튜닝 가중치 없이 KURE hybrid+cond 위에서 측정했다(v1/v2와 동일).
