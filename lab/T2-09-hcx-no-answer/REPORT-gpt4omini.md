# T2-09 LLM 리랭커 모델 교체 — HCX-007 vs gpt-4o-mini

- 일시: 2026-11-03 · 브랜치 `T2-09-hcx-prompt-v3`
- 설정: `hybrid+cond-gpt` (KURE hybrid + T2-14 조건 필터 → gpt-4o-mini 선택형 리랭커 top 20), `--split all`
- 바꾼 것: 모델만. 프롬프트(v3 `SYSTEM`·`user_message`)·파서·최대 5개 선택·후처리는 HCX와 같다.
  `OpenAIClient`(temperature 0, `response_format=json_object`, max_tokens 512, SDK 재시도 5회)
- 골든셋: `evals/datasets/retrieval_golden.jsonl` (sha256 e041d9ba…), dev 39문항(답 없음 10) · test 78문항(답 없음 18)
- 결과 폴더: `evals/reports/20261103-142212-T2-09-gpt4omini-v3` · 원표: `compare_output_gpt.md`

## 1. 결론

1. **답 없음 판정은 HCX와 비슷한 수준이다.** dev F1은 0.857로 전체 설정 중 최고다(v2-low 0.762, v3-none 0.696).
   test F1은 0.774로 v2-low(0.882), v3-none(0.813)보다 낮다. 두 split을 합치면 HCX 최선과 비슷하다.
   오거절은 dev 2/29, test 1/60으로 HCX low 수준이다.
2. **검색 순위는 둘로 갈린다.** Hit@5와 Hit@10은 전체 최고(test 43, 47)지만 Hit@1은 24로 HCX(29~33)보다 낮다.
   gpt는 평균 3.1개를 고르고, 고른 표는 stage-1 순서대로 앞에 놓인다. 그래서 1위 자리가 덜 정확해진다.
   gold는 고른 표 안에 들어오므로 Hit@5와 @10은 오른다.
3. **운영 면에서는 압도적이다.** 지연 p50 1.20 s, p95 1.92 s이고, 오류와 재시도는 0건이다.
   HCX는 429 rate limit 때문에 p95가 30~110 s까지 갔다.
   비용은 117문항에 입력 848k·출력 1.8k 토큰, gpt-4o-mini 공시가($0.15 / $0.60 per 1M) 기준 약 $0.13(문항당 약 $0.001)이다.
4. **권장:** 리랭커를 gpt-4o-mini로 바꾸는 것은 타당하다(속도·안정성 확보, 답 없음 F1은 비슷).
   다만 Hit@1이 떨어지는 문제를 함께 다뤄야 한다. 아래 §5의 "LLM이 고른 순서 유지"가 첫 후보다.

## 5. 다음 후보 (측정 안 함)

- **LLM이 고른 순서 유지:** `LLMReranker`는 고른 표를 stage-1 순서로 앞에 둔다. 프롬프트는 "질문과 가까운 순서"로
  고르라고 했으므로, 고른 순서를 그대로 쓰면 Hit@1 손실을 줄일 수 있다. 변경은 1줄이다.
- gpt-4o-mini 위에서 프롬프트를 dev로 다시 조정하기(v3는 HCX용으로 작성됐다).
