## 프로젝트 개요

**프로젝트명: 통계표 메타데이터를 활용한 통계표 안내 챗봇 개발**

사용자가 자연어로 원하는 통계 주제와 조건을 설명하면, 통계표의 제목·조사명·작성기관·기간·주기·분류·항목·경로를 검색하여 적합한 KOSIS 통계표와 바로가기 링크를 안내한다. 통계표를 찾지 못하거나 질문의 조건을 모두 만족하는 표가 없을 때는 그 이유와 확인 가능한 범위를 알려준다.

실전 프로젝트 1의 수치 조회·요약 기능에 앞서 **어떤 통계표를 사용해야 하는지 결정하는 검색 모듈**을 만드는 단계다. 이번 단계의 결과물 `search_tables()`는 이후 수치 분석·시각화 서비스에 연결할 수 있도록 통계표 ID와 선택 근거를 구조화해 반환한다.

| 구분             | 실전 프로젝트 1          | 실전 프로젝트 2                     | 종합 프로젝트                      |
| ---------------- | ------------------------ | ----------------------------------- | ---------------------------------- |
| 핵심 질문        | 이 표의 수치는 무엇인가? | 어느 표를 봐야 하는가?              | 표를 찾아 분석·시각화할 수 있는가? |
| 중심 기능        | 수치 조회·계산·요약      | 메타데이터 검색·순위 결정·경로 안내 | 검색·분석·시각화 통합              |
| 이번 계획의 범위 | 연계 대상                | **연구 및 구현 대상**               | 후속 연계 대상                     |

## 1. Problem Definition

### 1.1 문제점과 사용자 요구

KOSIS에서는 통계표 이름을 정확히 모르는 사용자가 질문의 핵심 개념, 대상, 지역, 기간, 주기를 조합해 원하는 표를 찾아야 한다. 비슷한 이름의 통계표가 여러 개 있거나, 제목에는 없지만 분류·항목에 필요한 정보가 들어 있는 경우에는 제목 검색만으로 적합한 표를 고르기 어렵다.

사용자는 **질문과 관련성이 높은 통계표, 그 표가 조건을 충족하는 이유, 확인된 기간·작성기관, 실제 접속 가능한 KOSIS 경로**를 한 번에 안내받아야 한다. 적합한 표가 없다면 존재하지 않는 표나 링크를 만들어 답해서는 안 된다.

### 1.2 연구 목표

1. 제공된 통계표 메타데이터를 통계표 ID 기준으로 정리하고 검색 가능한 색인을 만든다.
2. 자연어 질문에서 통계 주제와 지역·기간·주기·분류·항목 등의 조건을 추출한다.
3. 후보 검색과 관련성 평가를 거쳐 가장 적합한 통계표를 추천한다.
4. 추천 근거와 확인된 메타데이터를 바탕으로 경로 안내 응답을 생성한다.
5. 정답이 없거나 질문이 모호한 경우의 판단 기준을 만들고 검색 성능 및 실패 사례를 평가한다.

### 1.3 연구 범위와 데이터 전제

현재 로컬에서 확인한 `data/population/catalog.csv`에는 **인구 분야 통계표 2,364개**가 있으며, 통계표 ID·통계표명·상위 경로·기간 표시·KOSIS URL을 담고 있다. `data/population/table_metadata.zip`에는 통계표별 세부 메타데이터가 있으며, 작성기관·분류·항목 등 검색에 필요한 필드를 추출할 수 있다. 이번 연구의 기본 평가 범위는 이 **제공 카탈로그**로 고정한다.

사용자 예시인 **‘중소기업의 기술개발 투자비율’**은 인구 분야 카탈로그의 범위를 벗어날 가능성이 높다. 해당 조사와 통계표의 메타데이터가 추가로 제공되지 않으면 통계표명·작성기관·링크를 추정하지 않고, 현재 검색 범위에 없음을 안내한다. 다른 분야로의 확장은 해당 분야 메타데이터를 같은 색인 형식으로 추가한 뒤 평가한다.

## 2. 연구 질문과 가설

| ID  | 연구 질문·가설                                                                                 | 확인 방법                                               |
| --- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| H1  | 제목뿐 아니라 조사명·분류·항목을 함께 색인하면 제목 검색보다 적합한 표를 더 잘 찾을 수 있는가? | 제목 중심 BM25와 전체 메타데이터 BM25의 Hit@k·MRR 비교  |
| H2  | 어휘 검색과 의미 검색을 결합하면 표현이 다른 질문과 통계표명 사이의 간극을 줄일 수 있는가?     | BM25, 임베딩, 하이브리드 검색을 동일한 질문 세트로 비교 |
| H3  | 지역·기간·주기 등 조건을 순위 결정에 반영하면 비슷한 표 중 맞는 표를 더 자주 고를 수 있는가?   | 조건 포함 질문의 Top-1 적합률과 조건 충족률 비교        |

모든 실험은 동일한 메타데이터 버전과 평가 질문을 사용한다. 검색 방식을 한 번에 하나씩 바꾸고 성능, 응답 시간, 비용을 함께 기록한다.

## 3. 연구 방법

### 3.1 통계표 메타데이터 분석 및 정제

통계표 ID를 기본 키로 카탈로그와 세부 메타데이터를 결합한다. 다음 필드의 존재 여부와 형식을 검사한다.

| 필드            | 검색·안내에서의 역할                | 검증 항목                               |
| --------------- | ----------------------------------- | --------------------------------------- |
| 조사명·통계표명 | 통계 주제와의 직접 일치             | 누락, 중복 이름, 동의어                 |
| 작성기관        | 출처 안내와 후보 구분               | 기관명 누락·표기 차이                   |
| 통계표 ID       | 색인·추천 결과의 고유 식별자        | 중복·조인 불일치                        |
| 수록기간·주기   | 질문의 기간 조건 검증               | 표시 문자열과 실제 메타데이터의 차이    |
| 분류·항목       | 제목에 드러나지 않는 검색 조건 확인 | 계층 구조, 동명이항목, 과도하게 긴 목록 |
| 통계표 경로·URL | 바로가기와 출처 제시                | 빈 값, 형식 오류, 잘못된 표 ID          |

검색 문서는 기본적으로 **통계표 1개 = 색인 문서 1개**로 구성하고, 제목·조사명·기관·분류·항목·기간·주기를 구분된 필드로 유지한다. 긴 설명이나 항목 목록을 나눠 색인해야 할 때만 청킹을 적용한다. 나뉜 조각에는 원래 통계표 ID를 반드시 연결하고, 최종 추천은 조각이 아닌 통계표 단위로 합친다.

### 3.2 사용자 질의 분석

질문에서 통계 주제, 대상, 지역, 기간, 주기, 분류·항목, 요청 유형을 추출한다. 질의 분석 결과는 구조화된 필드로 저장하고, 질문에 명시되지 않은 조건은 임의로 채우지 않는다. ‘최근’, ‘지역별’, ‘투자비율’처럼 해석이 여러 개인 표현은 검색 가능한 후보를 살펴본 뒤 필요한 경우 확인 질문을 제시한다.

### 3.3 후보 검색과 통계표 선정

1. **기준선:** 통계표명과 조사명 중심의 어휘 검색(BM25).
2. **메타데이터 확장:** 분류·항목·기관·경로를 검색 필드에 추가.
3. **의미 검색:** 질문과 통계표 메타데이터의 임베딩 유사도 검색.
4. **결합 및 재정렬:** 어휘·의미 검색의 후보를 합친 뒤 주제 적합성, 항목 일치, 기간·주기·지역 조건, 표의 세부 수준을 검토해 순위 결정.
5. **선정 또는 보류:** 충족하지 못한 필수 조건과 후보 간 점수 차이를 확인하여 추천, 복수 후보 제시, 되묻기, 답 없음 중 하나를 선택.

도구는 기존 계획서의 방향에 맞춰 LangChain 검색기와 ChromaDB를 후보로 사용하되, 채택 여부는 기준선 대비 평가 결과로 판단한다. 재정렬 모델 역시 성능 향상이 응답 시간·비용 증가를 정당화할 때 도입한다.

### 3.4 안내 응답 생성

응답에는 **추천 통계표명, 조사명, 작성기관, 확인된 수록기간·주기, 통계표 ID, KOSIS 바로가기, 추천 이유와 충족하지 못한 조건**을 포함한다. 필드 값과 링크는 검색된 메타데이터에서만 가져오며, 생성 모델이 존재하지 않는 통계표나 URL을 작성하지 못하도록 구조화된 검색 결과를 검증한다.

**질문 예시 — 제공 카탈로그 안의 질문**

> “서울의 연도별 주민등록세대수를 확인할 수 있는 통계표를 찾아주세요.”

**안내 형식**

> 추천 통계표: [검증된 통계표명]  
> 조사명 / 작성기관: [메타데이터에서 확인한 값]  
> 수록기간·주기: [확인된 값]  
> 추천 이유: 질문의 지역·기간·항목 조건과 일치하는 내용  
> 통계표 바로가기: [해당 통계표의 KOSIS URL]

**범위 밖 질문 예시**

> “중소기업의 기술개발 투자비율을 확인할 수 있는 통계표를 찾아주세요.”

현재 인구 분야 카탈로그에서 해당 통계표를 확인하지 못한 경우에는 검색 범위가 인구 분야임을 밝히고, 관련 분야 메타데이터가 추가되면 다시 검색할 수 있음을 안내한다. 인구 분야의 비슷한 단어가 있는 표를 억지로 추천하지 않는다.

### 3.5 파이프라인과 입출력

```text
사용자 질문
  → 질의 조건 추출
  → 메타데이터 후보 검색(BM25 / 의미 검색)
  → 조건 검증·재정렬
  → 추천 / 복수 후보 / 되묻기 / 답 없음 판정
  → 메타데이터 기반 안내 응답 및 KOSIS 링크
```

`search_tables(question, filters)`는 최소한 통계표 ID, 순위, 충족한 조건, 미충족 조건, 추천 근거, 출처 URL과 판정 상태를 반환한다. 챗봇은 이 결과를 읽기 쉬운 문장으로 표시한다. 실전 프로젝트 1의 수치 계산 결과를 생성하거나 임의의 수치를 답하는 일은 이번 단계의 평가 범위에 포함하지 않는다.

## 4. 평가 계획

### 4.1 평가 질문 구성

**검색 평가 질문 100건 이상**을 별도로 작성하고, 정답 통계표 ID 또는 허용 가능한 통계표 ID 집합을 기록한다. 단순한 표명 검색뿐 아니라 동의어, 분류·항목 중심 질문, 지역·기간·주기 조건, 유사 표 구분, 여러 후보가 적합한 질문, 모호한 질문, 제공 카탈로그 밖의 질문을 포함한다. 정답은 사람이 메타데이터와 원본 KOSIS 경로를 대조해 검토한다.

### 4.2 지표와 오류 분석

| 평가 영역      | 지표                              | 확인할 문제                                                 |
| -------------- | --------------------------------- | ----------------------------------------------------------- |
| 후보 검색      | Hit@1, Hit@5, MRR                 | 정답 표가 후보에 들어왔는가, 얼마나 높은 순위인가           |
| 조건 일치      | 주제·지역·기간·주기·항목별 충족률 | 제목은 비슷하지만 요구 조건이 다른 표를 고르지 않는가       |
| 답 없음·되묻기 | 정밀도, 재현율, F1, 잘못된 거절률 | 없는 표를 만들어 추천하거나 찾을 수 있는 표를 놓치지 않는가 |
| 안내의 근거성  | 통계표 ID·기관·기간·URL 일치율    | 안내 필드가 실제 메타데이터와 일치하는가                    |
| 사용성·운영    | 사람 판정, 응답 시간              | 추천 이유가 이해되는가, 검색이 지나치게 느리지 않은가       |

실패는 **후보 검색 누락 / 순위 오류 / 조건 해석 오류 / 메타데이터 부족 / 범위 밖 질문의 잘못된 추천 / 링크 오류**로 분류한다. 특히 정답이 없는 질문을 맞는 표가 있는 질문과 분리해 평가한다. 목표 수치는 기준선 결과를 확인한 뒤 확정하며, 최종 보고서에는 개선 전후의 실제 측정값과 남은 실패 사례를 함께 제시한다.

| 순서 | 작업                                    | 확인 가능한 결과                      |

| 1    | 제공 메타데이터 필드·누락·중복 조사     | 필드 명세 및 데이터 품질 기록         |
| 2    | 통계표 단위 검색 문서와 평가 질문 작성  | 색인 데이터, 정답 ID가 있는 평가 세트 |

| 5    | 답 없음 판정, 안내 응답, 챗봇 연결      | 통계표 ID·링크가 검증되는 동작 결과   |
| 6    | 실패 사례 분석 및 보고                  | 최종 평가표와 개선 과제               |

## 6. 필수 산출물

1. **메타데이터 검색 및 통계표 추천 코드:** 표 ID를 유지하는 색인 생성과 `search_tables()` 함수.
2. **통계표 선택 기준 및 검색 전략 문서:** 필드 사용법, 후보 검색, 조건 검증, 재정렬, 답 없음 판정 기준.
3. **통계표 안내 챗봇:** 추천 이유와 확인된 메타데이터, KOSIS 바로가기를 보여주는 실행 가능한 인터페이스.
4. **검색 정확도 테스트 및 실패 사례 분석:** 평가 질문·정답, 기준선과 개선안의 지표, 대표 실패 및 보완 방향.

## 7. 기대 효과와 다음 단계 연계

사용자는 통계표명을 정확히 모르더라도 자연어 질문으로 적합한 표의 경로와 선택 이유를 확인할 수 있다. 연구 결과는 종합 프로젝트의 **통계표 검색 → 수치 조회·계산 → 요약·시각화** 흐름에서 검색 단계로 재사용한다. 다만 통계표 안내의 정확도는 제공된 메타데이터의 범위와 품질에 달려 있으므로, 평가 결과에도 그 범위를 명시한다.

## 8. 실행 방법 (T2-41 이후)

설정은 **셸 환경변수**로 둬요(코드는 `.env`를 읽지 않아요). 값 목록과 뜻은 [docs/config.md](docs/config.md), 옛 이름 → 새 이름은 [docs/migration.md](docs/migration.md)예요. 아래는 Windows cmd(레포 루트, conda env `kosis` 또는 `uv run`) 기준이고, bash는 `set X=` 대신 `export X=`, 경로 구분자 `;` 대신 `:`를 써요.

```bat
set PYTHONPATH=.;src;vendor\phase1;vendor\phase1\src
set KOSIS_WORKSPACE=%CD%
set CHROMA_HOST=localhost
set CHROMA_PORT=8001
set CHROMA_COLLECTION=<빌드가 출력한 컬렉션 이름>
set EMBED_CKPT=data\models\<임베더>.pt
set RERANK_CKPT=data\models\<리랭커>.pt
set HCX_API_KEY=<안내 LLM·2차 리랭커를 쓸 때>

REM 오프라인 DB 준비 (한 번): 표 등록부 -> 시군구 사전 -> Chroma 색인 [-> hq 질문 생성 -> 질문 색인]
docker compose up -d chroma
python scripts\kosis_build.py tables --data-dir <제공 데이터 폴더>
python scripts\kosis_build.py sigungu --data-dir <제공 데이터 폴더>
python scripts\kosis_build.py chroma --model bge-m3-ft
python scripts\kosis_build.py hq-build --model gpt-4o-mini        & REM 선택, OPENAI_API_KEY 필요
python scripts\kosis_build.py hq-index --build <build_id>          & REM 선택, 뒤에 set HQ_BUILD=<build_id>

REM 백엔드 데모 · 테스트
uvicorn backend.app.main:app --reload
python -m pytest -q
```

`python scripts\kosis_build.py`는 `python -m kosis_rag_build.cli`와 같은 명령·인자에 셸 환경을 기본값으로 넘겨요(`--help`로 확인). Docker로 띄울 때(`docker compose up --build`)는 compose가 `.env`를 컨테이너 환경으로 넣어요(`env_file`, Docker가 읽음). 코드에서 검색 모듈을 쓰는 법은 `docs/migration.md` 맨 끝 "종합 레포가 할 일"을 보세요.
